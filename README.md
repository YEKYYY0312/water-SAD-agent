# 给排水工程 AI 工作台

面向给排水工程的 AI 工作台，将规范检索、水力计算、设计文档与图纸处理接入同一条 Agent 工作流。

**模型负责理解与协作，工具负责计算，工程师负责最终确认。**



## 从问题到工程产物

| 任务 | Agent 如何协作 | 输出与边界 |
| :--- | :--- | :--- |
| **规范问答** | 混合检索、重排与引用校验，不通过则回流重查 | 可追溯的条款依据；正式引用需核对标准版本与来源 |
| **水力计算** | 工具执行流速、损失、管径、泵扬程等程序化计算 | 输入口径、计算结果与校验信息，不让模型口算替代工具 |
| **文档生成** | 结构化模板、数值与引用自检、人工审批 | 计算书与设计说明；真实润色与正式引用需独立验收 |
| **图纸处理** | DXF 解析、规则审查与参数化绘图 | 图纸、批注或审查结果；不等同任意 DWG 直读或自动审图验收 |
| **材料统计** | 按材质与规格聚合，保留管段来源 | Excel / CSV 材料表；自动抽取取决于图纸解析与规则覆盖 |

## 工作原理

```text
工程问题 / 文件
       ↓
上下文与权限 → Agent 工具调用 → 检索 / 计算 / 文档 / 图纸 / 材料
                         ↑                 ↓
                         └──── 校验与回流 ──┘
                                           ↓
                                  需要审批的产物 → 人工确认
                                           ↓
                                    结果 / 导出 / Trace
```

- **数值可核验**：计算与统计走程序化工具，保留输入和来源。
- **依据可追溯**：引用经过确定性校验；机制通过不代表真实问答质量达标。
- **动作有边界**：工具权限、预算、超时、人工确认与运行记录贯穿工作流。

技术底座：**Python · LangGraph · FastAPI · React · PostgreSQL · MCP**。

## 快速开始

### 本地离线体验

推荐 Python **3.12** 与 [uv](https://docs.astral.sh/uv/)。项目声明支持 Python 3.11–3.12。

```bash
git clone https://github.com/YEKYYY0312/water-SAD-agent.git
cd water-SAD-agent
uv sync --extra dev

# 程序化水力计算：不需要模型密钥
uv run python -m water_agent.cli --mode calc "DN150、Q=20L/s，求流速"

# 离线机制体验：使用脚本替身，不是真实模型答案
uv run python -m water_agent.cli --mock-generator "给水管道的设计秒流量如何确定？"
```


### 自托管 Web 工作台

Docker Compose 提供数据库、迁移、管理员初始化与应用服务。先按 [secrets 配置说明](secrets/README.md) 准备所需文件，再从仓库根目录运行：

```bash
docker compose up -d
```

未配置远程模型凭据时，真实问答不可用；远程模型调用费用由使用者承担。**公开源码不等于生产环境安全验收或资料分发授权。**

## 质量与使用边界

这里区分三个层次，不把它们混成一个“准确率”：

1. **离线机制层**：检验工具调用、校验、审批、隔离与恢复契约。
2. **真实质量层**：使用真实模型、语料和独立评测，验证问答与工程产物。
3. **工程交付层**：核对正式规范、项目条件、图纸覆盖与部署安全，由工程师确认。


```bash
bash scripts/ci_gate.sh
```
