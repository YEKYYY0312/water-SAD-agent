# P5 任务简报：误报率验证

**状态**: 🔜 待启动

**预计工时**: 2-4 小时

## 一、任务目标

验证图纸审查功能的**误报率**（False Positive Rate），使用 P2.5 阶段建立的阴性集（18 张无缺陷图纸）。

**核心问题**：
- P4 为提高召回率放宽了 `check_min_diameter` 规则（不再要求 `system=drainage`）
- 这可能导致非排水管（如给水管 DN200）被误判为违规
- 需要验证这个改动是否引入了不可接受的误报

---

## 二、验收标准

### 2.1 定量指标

**误报率** ≤ 10%（每 10 个检出中，至多 1 个是误报）

**计算方式**：
```
误报率 = 误报数 / 总检出数
```

**示例**：
- 18 张阴性图纸，总共检出 20 个 findings
- 其中 2 个是误报（如给水管 DN200 被误判为排水管）
- 误报率 = 2 / 20 = 10% ✅

### 2.2 定性要求

1. **可解释性**：每个检出必须有清晰的证据链（handle → evidence_handles → detail）
2. **误报可归因**：如果误报率 > 10%，能明确指出是哪类误报（系统类型混淆 / 管径阈值 / 标注关联错误）
3. **改进方向清晰**：如果需要调整，知道要改什么参数或逻辑

## 三、执行步骤

### 3.1 准备评测脚本

**文件**: `scripts/eval_drawing_p5_fp.py`

**功能**：
1. 读取阴性集清单（`data/eval/drawing_p1/README.md` 中标记为 `role: negative`）
2. 对每张图纸运行 `review_drawing_graph`
3. 统计检出数量、人工标注误报、计算误报率

**输出**：
```json
{
  "summary": {
    "total_drawings": 18,
    "total_findings": 25,
    "false_positives": 2,
    "fp_rate": 0.08
  },
  "details": [
    {
      "drawing_id": "D-01",
      "findings": [...],
      "false_positives": [
        {
          "rule_id": "drain.min_diameter",
          "handle": "123",
          "reason": "给水管 DN200 被误判为排水管"
        }
      ]
    }
  ]
}
```

### 3.2 执行评测

```bash
# 1. 运行评测（生成初步结果）
python scripts/eval_drawing_p5_fp.py

# 2. 人工审核 findings（标注误报）
# 编辑 data/eval/drawing_p5_fp_annotations.json
# 对每个 finding，标记 is_false_positive: true/false

# 3. 重新计算指标
python scripts/eval_drawing_p5_fp.py --with-annotations

# 4. 生成报告
python scripts/eval_drawing_p5_fp.py --report
```

### 3.3 分析结果

**如果误报率 ≤ 10%** → P5 通过，继续 P6

**如果误报率 > 10%** → 分析误报类型，调整规则：

1. **系统类型混淆**（如给水管被误判为排水管）
   - 方案 A：恢复 `system=drainage` 要求，但从标注文本推断系统类型
   - 方案 B：增加管径范围区分（DN50-150 更可能是给水，DN200+ 更可能是排水）
   - 方案 C：在 detail 中降低断言强度（"可能为排水管" → "疑似排水管，需人工确认"）

2. **标注关联错误**（标注被关联到错误的管段）
   - 缩小 `ANNOTATION_MATCH_RADIUS`（20 → 15）
   - 增加图层优先级（同图层优先）

3. **管径阈值过严**（DN250 被判违规，但实际场景允许）
   - 调整阈值（300 → 250）
   - 或改为 warning 级别，不作为强制违规

## 四、关键设计决策

### 4.1 阴性集的定义

**当前定义**：`role: negative` 的 18 张图纸，预期 **0 个真实缺陷**

**注意**：
- "0 个真实缺陷" 不等于 "0 个检出"
- 可能存在真实的但不严重的问题（如 DN280 < DN300，但在某些场景下可接受）
- 人工审核时需要结合工程实践判断

### 4.2 误报的定义

**严格定义**：检出的问题在工程上完全不成立（如给水管被误判为排水管）

**宽松定义**：检出的问题虽然在工程上可疑，但证据不足或断言过强

**建议采用严格定义**，理由：
- 宽松定义会导致大量边界 case 的主观判断
- 严格定义下的误报率更能反映系统的"硬伤"
- 如果严格定义下误报率已 > 10%，说明需要立刻修复

### 4.3 召回率与误报率的权衡

**当前状态**：
- 召回率：100%（P4 验证）
- 误报率：未知（P5 待验证）

**权衡原则**：
- 设计审查场景：**宁可漏报，不要误报**（误报会浪费审图人员时间）
- 施工审查场景：**宁可误报，不要漏报**（漏报可能导致工程事故）

**当前倾向**：设计审查，故如果 P5 误报率 > 15%，应该牺牲部分召回率换取更低误报率。

## 六、风险与缓解

### 6.1 人工标注成本过高

**风险**：18 张图纸 × 平均 5 个 findings = 90 个标注，耗时 2-3 小时

**缓解**：
1. 优先标注高频规则（如 `drain.min_diameter`）
2. 建立标注指南，减少主观差异
3. 使用 LLM 辅助标注（生成初步判断 + 理由，人工确认）

### 6.2 误报率计算的分母问题

**风险**：如果总检出数很少（如只有 3 个），1 个误报就是 33% 误报率

**缓解**：
1. 报告中同时给出绝对值（2/20）和百分比（10%）
2. 如果总检出数 < 10，标记为"样本不足，需补充阴性集"

### 6.3 阴性集质量问题

**风险**：阴性集可能包含真实缺陷（只是我们没发现）

**缓解**：
1. P2.5 已经人工审核过阴性集，确认无明显缺陷
2. 如果评测中发现"误报"实际是真实缺陷，将其移出阴性集并记录
