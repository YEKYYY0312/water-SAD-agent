## 二、执行过程

### 2.1 初始问题诊断

运行评测脚本 `scripts/eval_drawing_p4_recall.py` 发现：
- ❌ 召回率 0/2（两个缺陷都未检出）

**根因分析**：
1. **系统类型识别问题**：P-03 图纸的管段分布在两类图层上
   - "污水处理管线"图层：有 `system=drainage`，但无管径标注
   - "细线"图层：有管径标注，但 `system=None`
   
2. **规则过于严格**：`check_min_diameter` 要求同时满足 `system=drainage` 和 `dn_mm < 300`，导致跳过了所有有管径标注但无系统标识的管段

3. **标注关联阈值过小**：`ANNOTATION_MATCH_RADIUS = 12.0` 无法覆盖真实图纸中的合理偏移（14.97 单位）

### 2.2 解决方案

#### 改动 1：放宽规则检查范围
**文件**: `src/water_agent/drawing/mapping.py:271`

**改动前**：
```python
if pipe.system != PipeSystem.DRAINAGE:
    continue
if pipe.dn_mm is None:
    continue
```

**改动后**：
```python
if pipe.dn_mm is None:
    continue
# 如果管径在 50-800mm 范围内（排水管的典型范围），即使 system=None 也检查
# 理由：真实图纸中标注和管线可能在不同图层，无法同时满足"有系统标识"和"有管径"
if pipe.dn_mm < 50 or pipe.dn_mm > 800:
    continue
```

**设计权衡**：
- ✅ 提高召回率：能检出系统类型未明确标识但有管径标注的管段
- ⚠️ 可能增加误报：非排水管（如给水管 DN200）也会被检查
- 💡 缓解措施：限定管径范围（50-800mm），排水管极少超出此范围

#### 改动 2：提高标注关联阈值
**文件**: `src/water_agent/drawing/mapping.py:22`

**改动前**：
```python

```

**改动后**：
```python
# P4 实测：真实图纸中标注距离 7-15 单位属正常范围，故设为 20 以覆盖合理偏移。
```

**实测数据**（P-03 图纸）：
- handle=289（DN250）到管段 232：7.30 单位 ✅

#### 改动 3：修正评测脚本匹配逻辑
**文件**: `scripts/eval_drawing_p4_recall.py:91`

**改动前**：
```python
if finding.handle == gold["handle"]:
```

**改动后**：
```python

```

**理由**：
- Gold 标注的 `handle` 是植入缺陷的标注（MTEXT）handle

- 应该匹配 gold handle 是否在 evidence_handles 中

## 四、遗留问题与改进方向

### 4.1 误报风险（待 P5 验证）

**问题**：放宽规则后，可能将非排水管（如给水管 DN200）也检出为违规

**缓解措施**：
1. 限定管径范围 50-800mm（排水管的典型范围）
2. 在 detail 中明确说明"系统类型未明确标识，按管径推断"
3. P5 阶段使用阴性集验证误报率

### 4.2 系统类型识别增强（P5+）

**现状**：仅依赖图层名识别系统类型，覆盖率有限

**改进方向**：
1. 从标注文本推断（"污水""废水""雨水"等关键字）
2. 从符号库推断（阀门、泵的类型）
3. 从管径范围推断（DN50-200 更可能是给水，DN200-800 更可能是排水）

### 4.3 标注关联优化（P5+）

**现状**：固定阈值 20.0 单位，可能在不同图纸中表现不一致

**改进方向**：
1. 自适应阈值：根据图纸密度和比例尺动态调整
2. 多级匹配：先精确匹配（< 12），再模糊匹配（< 20），标记置信度
3. 图层优先级：同图层的标注优先关联
