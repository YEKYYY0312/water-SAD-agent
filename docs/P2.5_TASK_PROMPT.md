# P2.5 任务：人工标注真实图纸缺陷 Ground Truth

## 🎯 任务目标

对 P2 采集的 18 份真实图纸样本进行**人工审查**，标注出所有违反给排水设计规范的缺陷，建立 `drawing_p1` 真实评测集。

这是验证 P3 图纸审查链路**真实召回率**的前置任务——没有人工标注的 gold，就无法评估系统在真实图纸上的表现。

## 🔍 标注范围与边界

### ✅ 需要标注的缺陷类型

根据 P3 图纸审查链路的能力边界，**只标注以下 6 类缺陷**：

#### 1. 管径不符（最高优先级）
- **定义**: 管道标注的管径不符合规范要求
- **示例**: 
  - ❌ 生活给水管 DN15（规范要求 ≥DN20）
  - ❌ 排水立管 DN50（规范要求 ≥DN75）
  - ❌ 消防管 DN80（规范要求 ≥DN100）
- **判定依据**: GB50015-2019 表 3.5.2、3.6.3、8.2.2 等

#### 2. 标高不合理
- **定义**: 管道标高违反规范或与相邻设施冲突
- **示例**:
  - ❌ 给水管低于排水管（交叉点）
  - ❌ 地漏标高高于地面完成面
  - ❌ 水箱溢流管口低于进水管
- **判定依据**: GB50015-2019 §3.8.11、§4.7.5 等

#### 3. 材料选用错误
- **定义**: 管道材料不符合使用场景
- **示例**:
  - ❌ 热水管使用 PVC（应用 PP-R 或铜管）
  - ❌ 室外埋地给水用镀锌钢管（应用 PE 或球墨铸铁）
  - ❌ 消防管使用 PPR（应用钢管）
- **判定依据**: GB50015-2019 §3.5.4、§3.6.5 等

#### 4. 坡度不足
- **定义**: 排水管坡度小于规范要求
- **示例**:
  - ❌ DN100 排水横管坡度 0.005（规范要求 ≥0.012）
  - ❌ 雨水管坡度 0.002（规范要求 ≥0.005）
- **判定依据**: GB50015-2019 表 4.3.5

#### 5. 缺少必要设施
- **定义**: 缺少规范要求的附件或设备
- **示例**:
  - ❌ 排水立管未设置检查口
  - ❌ 给水管道未设置水表
  - ❌ 排水横管转角处未设置清扫口
- **判定依据**: GB50015-2019 §4.8.4、§3.3.14 等

#### 6. 间距/位置不合规
- **定义**: 设施布置违反规范要求的间距或位置
- **示例**:
  - ❌ 给水管与排水管水平净距 < 0.5m
  - ❌ 地漏距离墙面 > 2.0m
  - ❌ 水表安装在冻土层以上
- **判定依据**: GB50015-2019 §3.8.11、§4.7.3 等

### ❌ 不标注的内容（超出 P3 能力边界）

以下内容**不属于 P2.5 标注范围**，即使在图纸上看到也跳过：

1. **图纸完整性问题**（图签栏缺项、比例尺错误、图层混乱）
2. **制图规范问题**（线型不统一、文字高度不合规、标注样式）
3. **设计深度问题**（细部构造缺失、节点大样不足）
4. **计算类缺陷**（流量计算错误、水力计算偏差）—— P3 链路不做水力计算
5. **系统性问题**（总体布局不合理、竖向设计不当）—— 需要多张图纸综合判断
6. **非给排水专业缺陷**（结构、电气、暖通等）

## 📋 标注格式规范

### 输出文件结构

为每张图纸创建一个独立的标注文件：

```
data/eval/drawing_p1/
├── annotations/
│   ├── D-01.json          # 大样图 1 的标注
│   ├── D-02.json
│   ├── D-03.json
│   ├── P-01.json          # 平面图 1 的标注
│   ├── P-02.json
│   ├── ...
│   ├── PUMP-03.json
│   └── S-05.json
├── drawing_p1.jsonl       # 汇总的评测集（最终格式）
└── README.md              # 标注说明和统计
```

### 单个标注文件格式 (JSON)

```json
{
  "drawing_id": "P-01",
  "drawing_type": "平面图",
  "annotation_date": "2026-09-15",
  "annotator": "人工审查",
  "total_defects": 3,
  "defects": [
    {
      "defect_id": "P-01-D001",
      "category": "管径不符",
      "severity": "高",
      "description": "生活给水立管 DN15 不符合规范要求",
      "location": {
        "layer": "给水",
        "approx_position": "1轴与A轴交点附近",
        "entity_type": "TEXT",
        "entity_content": "DN15"
      },
      "regulation": {
        "spec": "GB50015-2019",
        "clause": "3.5.2",
        "requirement": "生活给水立管管径不应小于 DN20"
      },
      "expected": "DN20 或更大",
      "actual": "DN15",
      "notes": "该立管服务 3 层住户，按用水定额计算流量应选用 DN20"
    },
    {
      "defect_id": "P-01-D002",
      "category": "标高不合理",
      "severity": "中",
      "description": "给水管与排水管交叉处标高冲突",
      "location": {
        "layer": "给水+排水",
        "approx_position": "B轴与2轴交点",
        "entity_type": "LINE",
        "entity_content": "给水管标高 -0.500, 排水管标高 -0.450"
      },
      "regulation": {
        "spec": "GB50015-2019",
        "clause": "3.8.11",
        "requirement": "给水管应敷设在排水管上方，垂直净距不小于 0.15m"
      },
      "expected": "给水管标高应 ≥ -0.300",
      "actual": "给水管 -0.500 < 排水管 -0.450",
      "notes": "建议给水管抬高至 -0.300 或排水管降低至 -0.650"
    }
  ]
}
```

### 字段说明

#### 缺陷级别 (severity)

- **高**: 直接违反强制性条文，影响使用功能或安全
- **中**: 违反推荐性条文，影响使用便利性或经济性
- **低**: 不符合最佳实践，但不违反规范（P2.5 不标注此类）

#### 位置描述 (location)

由于 DXF 解析后的实体是扁平列表，**无法直接引用图纸上的坐标**，因此用**近似位置描述**：

- `layer`: 所在图层名称（从 MANIFEST.md 可查到图层列表）
- `approx_position`: 文字描述位置（如"1轴与A轴交点"、"左上角卫生间"）
- `entity_type`: 相关实体类型（TEXT / LINE / CIRCLE / INSERT 等）
- `entity_content`: 实体内容摘要（如标注文字 "DN15"、管道标高 "-0.500"）

**重要**: 位置描述要**足够具体**，让后续验证者能在图纸上找到该缺陷。

#### 规范依据 (regulation)

- `spec`: 规范编号（如 GB50015-2019）
- `clause`: 条款号（如 3.5.2）
- `requirement`: 规范原文要求（简短摘录）

**必须**有规范依据，不能仅凭经验判断。

## 🛠️ 标注流程（7 步）

### Step 1: 准备工作

```bash
# 1. 创建标注目录
mkdir -p data/eval/drawing_p1/annotations

# 2. 查看样本清单，了解每张图纸的基本信息
cat data/drawings/real_samples/MANIFEST.md

# 3. 准备规范文档（放在 data/specs/ 目录下）
ls data/specs/
# 应包含: GB50015-2019.pdf, GB50013-2018.pdf, GB50014-2021.pdf, GB50318-2017.pdf
```

### Step 2: 图纸可视化（使用 CAD 软件打开 DXF）

**推荐工具**（按优先级）：
1. **AutoCAD** (最佳，完整支持)
2. **LibreCAD** (开源免费)
3. **DWG FastView** (在线查看器)
4. **DraftSight** (免费版)

**打开图纸后的检查清单**：
- [ ] 图纸能否正常显示（无乱码、无丢失图元）
- [ ] 图层是否清晰（给水、排水、消防等分层）
- [ ] 标注是否可读（管径、标高、材料标注）
- [ ] 是否有图例说明（管材代号、符号含义）

### Step 3: 逐张图纸审查（每张约 30-60 分钟）

**审查顺序**（从易到难）：
1. **先审查系统图** (S-01 ~ S-05)：系统简单，缺陷类型集中（管径、标高、坡度）
2. **再审查大样图** (D-01 ~ D-03)：细节清晰，缺陷易识别
3. **最后审查平面图和泵房图** (P-01 ~ P-07, PUMP-01 ~ PUMP-03)：内容复杂，需要对照规范仔细核查

**审查检查点**（按缺陷类型）：

#### 3.1 管径检查
- [ ] 给水立管 ≥ DN20（住宅）、≥ DN25（公建）
- [ ] 排水立管 ≥ DN75（住宅）、≥ DN100（公建含大便器）
- [ ] 消防管 ≥ DN100（室内）、≥ DN150（室外）
- [ ] 雨水立管按汇水面积查表核算

#### 3.2 标高检查
- [ ] 给水管在排水管上方（交叉处垂直净距 ≥ 0.15m）
- [ ] 地漏标高低于地面完成面 5-10mm
- [ ] 水箱溢流管口高于进水管浮球阀
- [ ] 排水管道无倒坡（起点标高 > 终点标高）

#### 3.3 材料检查
- [ ] 生活给水冷水管：PP-R / PE / 不锈钢
- [ ] 生活给水热水管：PP-R / 铜管 / 不锈钢（不用 PVC）
- [ ] 排水管：PVC-U / HDPE / 铸铁
- [ ] 消防管：镀锌钢管 / 不锈钢（不用塑料管）

#### 3.4 坡度检查
- [ ] 排水横管 DN50: i ≥ 0.025
- [ ] 排水横管 DN75: i ≥ 0.015
- [ ] 排水横管 DN100: i ≥ 0.012
- [ ] 排水横管 DN125: i ≥ 0.010
- [ ] 雨水管: i ≥ 0.005

#### 3.5 设施检查
- [ ] 排水立管底部设置检查口（距地面 1.0m）
- [ ] 排水横管转角 > 135° 处设置清扫口
- [ ] 给水管道设置水表
- [ ] 排水管道设置存水弯（防臭）

#### 3.6 间距检查
- [ ] 给水管与排水管水平净距 ≥ 0.5m
- [ ] 热水管与冷水管间距 ≥ 0.2m
- [ ] 地漏距最远卫生器具 ≤ 2.0m

### Step 4: 规范条文查证

**对于每个疑似缺陷**，必须：
1. 找到对应的规范条款（用 PDF 搜索功能）
2. 摘录规范原文要求
3. 判断是否确实违反（有些是推荐，不是强制）

**快速查找技巧**：
- 管径要求：搜索"管径"、"公称直径"
- 标高要求：搜索"标高"、"敷设"、"垂直净距"
- 材料要求：搜索"管材"、"材质"
- 坡度要求：搜索"坡度"、"坡度表"
- 设施要求：搜索"检查口"、"清扫口"、"水表"

### Step 5: 填写标注文件

为每张图纸创建一个 JSON 文件（参考上面的格式），**逐条录入缺陷**。

**注意事项**：
- 每个缺陷必须有唯一 ID（格式：`{drawing_id}-D{序号}`，如 `P-01-D001`）
- 位置描述要具体（能让他人在图纸上找到）
- 规范依据要准确（spec + clause + requirement）
- `expected` 和 `actual` 要明确对比

**质量检查**：
- [ ] 每个缺陷都有规范依据
- [ ] 位置描述足够具体
- [ ] 严重程度判断合理
- [ ] JSON 格式正确（用 `jq` 或在线工具验证）

### Step 6: 汇总生成 `drawing_p1.jsonl`

将所有单图标注文件汇总成评测集格式：

```python
# 创建汇总脚本: scripts/merge_drawing_annotations.py

import json
from pathlib import Path

def merge_annotations(annotations_dir: Path, output_file: Path):
    """将单图标注汇总为评测集 JSONL 格式。"""
    
    all_cases = []
    
    for json_file in sorted(annotations_dir.glob("*.json")):
        with open(json_file, encoding="utf-8") as f:
            annotation = json.load(f)
        
        # 为每个缺陷生成一条评测案例
        for defect in annotation["defects"]:
            case = {
                "drawing_id": annotation["drawing_id"],
                "defect_id": defect["defect_id"],
                "query": f"审查图纸 {annotation['drawing_id']}",
                "gold_defects": [
                    {
                        "category": defect["category"],
                        "description": defect["description"],
                        "regulation": defect["regulation"],
                        "location": defect["location"],
                    }
                ],
                "metadata": {
                    "drawing_type": annotation["drawing_type"],
                    "severity": defect["severity"],
                }
            }
            all_cases.append(case)
    
    # 写入 JSONL
    with open(output_file, "w", encoding="utf-8") as f:
        for case in all_cases:
            f.write(json.dumps(case, ensure_ascii=False) + "\n")
    
    print(f"✅ 生成评测集: {output_file}")
    print(f"   总案例数: {len(all_cases)}")

if __name__ == "__main__":
    annotations_dir = Path("data/eval/drawing_p1/annotations")
    output_file = Path("data/eval/drawing_p1.jsonl")
    merge_annotations(annotations_dir, output_file)
```

运行汇总：
```bash
_venv/bin/python scripts/merge_drawing_annotations.py
```

## ⚠️ 注意事项

### 1. 标注一致性

- **同一类缺陷**的描述方式要一致（如都用"管径不符"，不混用"管径过小"）
- **规范引用**格式统一（都用"GB50015-2019 §3.5.2"，不混用"GB50015 第3.5.2条"）

### 2. 避免过度标注

- **不标注主观判断**（如"布局不美观"、"设计不经济"）
- **不标注超出能力边界的缺陷**（如需要多图纸综合判断的系统性问题）
- **不标注制图规范问题**（线型、文字、图层命名等）

### 3. 标注质量 > 数量

- 宁可少标几条，也要保证每条都**有规范依据、位置准确、描述清晰**
- 如果某张图纸确实没有明显缺陷，可以标注 0 条（但要在 notes 里说明"经审查未发现规范违反项"）

### 4. INSERT 块内容不可见的影响

由于当前 `dxf_reader` **不展开 INSERT 块**，块内的文字和几何对审查链路**不可见**。

**处理方式**：
- **PUMP-03** (3,285 个 INSERT，占 57%)：**只标注块外可见的缺陷**
- 在该图纸的 `notes` 里说明："本图大量使用块引用，块内内容对当前审查链路不可见，实际缺陷数可能更多"

P3 完成 INSERT 展开后，需要**重新审查 PUMP-03** 并补充标注。
