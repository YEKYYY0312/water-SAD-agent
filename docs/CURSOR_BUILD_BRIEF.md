## 给 Cursor 的指令（直接粘贴）

你是给排水领域 AI Agent 的**主工程实现者**。请严格依据本项目的设计文档与工程原则，按
**MVP 优先**、**Harness Engineering（评测先行）** 与 **Loop Engineering（循环工程）** 来搭建，
不得跳过阶段、不得自作主张更换技术栈。

### 一、开工前必读设计文档（先读懂再动手）
1. `docs/design/00-overview-and-decisions.md` —— 愿景、技术栈、当前已确认约束与未锁定 ADR
2. `docs/design/01-architecture.md` —— 分层架构与模块职责、依赖方向
3. `docs/design/02-loop-engineering.md` —— LangGraph 循环设计（状态/主图/各子图 Loop/Human-in-loop）
4. `docs/design/03-harness-engineering.md` —— 评测框架（分层、判分策略、评测集格式）
5. `docs/design/04-file-reading-and-mcp.md` —— 文件读取、MCP 架构
6. `docs/design/05-frontend.md` —— React 前端
7. `docs/design/06-roadmap.md` —— 分阶段计划 + **每阶段验收标准**
8. `docs/design/07-worked-example.md` —— 端到端走查（理解完整数据流）

### 二、技术栈与硬约束（不得偏离）
- **Python 3.11 或 3.12** 虚拟环境（**不要用 3.13/3.14**，TriviumDB 等依赖缺 wheel）
- 编排：**LangGraph**（StateGraph + checkpointing + interrupt）
- 组件/RAG：**LangChain** + **TriviumDB**（向量×图谱×文档，自带 BM25+向量多路召回，用 `search_hybrid`）
- 工具标准化：**MCP**；后端：**FastAPI**；前端：**React + TypeScript + Vite**
- 观测：LangSmith / Langfuse；评测：自建 **harness**

### 三、工程原则（每条都必须在实现中体现）
1. **计算类永远走程序化校验**：数值由真实水力计算工具算，LLM 只做参数理解与结果解释，绝不让 LLM 口算。
2. **引用可追溯**：每个回答能指回「规范号 + 条款号」，禁止编造不存在的条号。
3. **Human-in-the-loop**：生成正式文档/设计说明前设 `interrupt` 确认点，可暂停/恢复。
4. **评测先行**：每个阶段连同其评测集一起交付；改动不得使关键指标（计算判分精度、规范引用正确率）显著下降。

### 四、当前设计决策
- **ADR-01** 沿程水头损失：**不锁定具体公式**；计算输入和评测用例必须显式指定公式，缺失时不得静默选择。
- **ADR-02** 检索粒度：**结构化父子级切块** —— 父块（章/节）只补上下文，子块（条/款/项/表）进入 TriviumDB；检索命中子块后按 `parent_id` 回填父块上下文，最终引用仍绑定具体条款。
- **ADR-03** 图纸审查：**规则引擎为主** + Vision 辅助。
- **ADR-04** Human-in-loop：仅在**生成正式文档/设计说明前**设确认点。
- **ADR-05** 判分权重：计算=程序化硬门槛（误差 ≤1%）；引用=精确到条；两者不妥协。

### 五、分阶段实现（每个阶段完成后再开始下一个）

**P0 —— 项目骨架 + Harness 基础 + 最小 RAG 环**
- 项目结构、依赖(requirements/pyproject)、Python(3.11/3.12) 环境
- harness 跑分器骨架（数据加载/指标/报告/CI 返回值）
- 最小 RAG 环：`提问 → TriviumDB search_hybrid → mock 生成器 → 带引用回答`
- 本地 JSON trace；最小规范问答 fixture（10 条）
- ✅ 通过门槛：harness 能跑 jsonl 并输出通过率；失败用例使 CI 非零；一次调用有完整 trace

**P1 —— 规范问答 + 水力计算（核心 MVP）**
- 结构化父子级切块：章/节父块 + 条/款/项/表子块，递归切块兜底
- 子块入 TriviumDB，父块持久化回填；检索命中后返回子块 + 父块上下文
- RAG 子图完整环（检索/生成/引用自检/retry 回流）
- 计算子图完整环（参数解析/程序化校验/越界回环调参）+ 水力计算工具集（流速/沿程损失/管径/泵扬程/排水坡度）
- 自研 MCP：水力计算 server + 规范库检索 server
- 金标准：规范问答 ≥50 条 + 计算案例 ≥20 条（锁定口径）
- ✅ 通过门槛：计算用例程序化判分通过率 ≥95%；规范引用可追溯不编造；父子块检索不重复

**P2 —— 计算书/设计说明生成 + 材料统计**（文档子图 + Excel 材料 + Human-in-loop）
**P3 —— 图纸读取与审查（DWG，最难）**（DWG 解析/对象映射/规则引擎/缺陷标注；缺陷召回 ≥80%）
**P4 —— MCP 扩展**（接入 CAD/BIM 与企业库，写操作需人工确认）
**P5 —— React 前端**（聊天流式/上传/工具可视化/引用卡片/计算卡片/图纸预览/反馈回流）

### 六、工作方式要求
- **一次专注一个阶段**：写完 P0 并跑通其验收标准后，停下来做一个小结再进 P1，不要一次铺完所有阶段。
- **每阶段提交**：用语义清晰的 git 提交；每阶段一个 tag 基线。
- **测试先于、贯穿**：每个工具/子图都有测试；hydraulics 用「物理参考值回归」锁住公式。
- **遇到歧义先问**：真实规范条款目录由用户提供。在真实目录提供前，P0 只能使用项目内 fixture；不得假设某个相对或绝对路径存在。
- **优先级**：`计算正确性 > 引用可追溯 > 更多能力`。P1 的「会算 + 会查规范」是本项目核心，其余是放大器。
