# P4.5 Step 30 决策记录：可信设计引用与重算语义

**日期**：2026-09-11
**状态**：Implemented
**范围**：仅收紧 `multi_agent` Design Agent 的引用、计算支撑、系统缺参和重算请求语义；不改旧
`qa`、`docgen`、`drawing_review` 路径，不新增公式、RAG、图纸或编排实现。

## 结论

1. `user_constraints` 中的 `source_id` 只是用户请求，绝不是可信引用来源。Design Agent 只会采用本轮
   `retrieved_source_ids` 或已由 citation validator 交入的 `CitationClaim`；其他 ID 写入
   `invalid_citation_ids`，不进入任何管段 `source_ids`，设计 envelope 为 `blocked`。
2. `DesignPackage.citations` 记录每个实际引用的 `source_id`、`spec_version`、`version_status` 和
   `segment:<segment_id>:source_ids` 位置。保留既有 `DesignPipeSegment.source_ids`，因此不改变绘图、
   审查和文档适配器的读取路径。
3. `verified` 只允许使用当前、成功的 CalcPackage 中 `status=verified` 且有 `outputs` 的活动
   `calc_case_id`。CalcPackage 或 envelope 存在失败、缺参、非 `ready` 状态，或 case 不在编排器提供的
   `active_calc_case_ids` 集合时，管段为 `not_verified`。
4. 空 `ProjectBrief.systems` 不再回退为 `water_supply`。此时不生成管段，显式记录
   `missing system: brief.systems empty`，DesignPackage 为 `missing_inputs`。
5. 上一版设计字段差异和编排器传入的任意新增水力输入都会生成结构化
   `recalculation_requests`；相关管段改为 `recalc_required`，直到新的水力结果回流，envelope 不能为
   `ready`。
6. `segment_id` 继续由 `project_id/start_node_id/end_node_id/system` 的确定性 SHA-256 派生；多边拓扑重复
   执行的 ID 集合和 payload hash 保持稳定。

## 验证

- `tests/test_multi_agent_design.py` 覆盖未知 source_id 注入、validator 已验证引用的版本和位置、过期
  calc case、失败 calc、空 systems、新水力输入重算，以及多管段 ID 稳定性。
- `tests/test_multi_agent_contracts.py` 与现有 P4.5 契约一起运行，确保新增引用记录仍受
  `extra=forbid` 和 canonical payload hash 保护。

## 残余限制

- Design Agent 不自行调用水力工具，也不判断公式；它只消费由 Hydraulic Agent 产出的结构化结果。
- 版本状态来自既有 citation validator/VersionRegistry。当前规范版本仍可能为 `unknown`，该事实会保留在
  引用记录中，不能被 Design Agent 伪造为 `current`。
