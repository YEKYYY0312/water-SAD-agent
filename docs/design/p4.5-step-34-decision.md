# P4.5 Step 34 Decision: Evidence-Driven Evaluation

Date: 2026-09-11

## Decision

- `multi_agent_p0` metrics are computed from measured per-case evidence and
  structured runtime trace events. A green case list never upgrades a metric to
  a perfect value.
- Detectors are derived after execution from trace facts: approval-binding
  failures, export attempts, routing exhaustion, provenance state, stale reuse
  attempts, and final review state. Case IDs and prefilled detector fields are
  not detector inputs.
- Expected blocks are test successes only when the real release gate/routing
  operation produced the expected blocked state. Reports retain both the
  workflow `status` and evaluation `outcome` (`pass`, `fail`, `skip`, or
  `blocked`). Missing keys can produce `skip` only for an explicit real-quality
  case; a real component failure is `blocked` and the CLI exits non-zero.
- Final DXF export now requires an approved, current `ApprovalRecord`; missing,
  rejected, or stale approval fails before the copy side effect.
- Baseline comparison accepts only reports generated by the Step 34 harness and
  recomputes metrics from their evidence/trace before comparing thresholds.

## Verification

- Behavior coverage validates approval hash invalidation, unapproved export,
  release failure, and bounded routing instead of existence-only assertions.
- Added metric regression coverage proving that all `passed=True` cases cannot
  force any unmeasured or failed metric to `1.0`.

## Residual Risk

This remains an offline synthetic mechanism suite. Its metrics prove the
instrumented P0 behavior only; they do not establish real-model quality or
real-project drawing recall.
