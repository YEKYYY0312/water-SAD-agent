# P4.5 Step 32 决策记录：只读 Review 与证据化路由

**日期**：2026-09-11
**状态**：Implemented
**范围**：只调整 `multi_agent` 的 Review 聚合与确定性路由证据；不修改既有
`qa`、`docgen`、`drawing_review` 路径，也不复制公式、RAG 或图纸实现。

## 决策

1. `ReviewPackage.reviewed_artifact_hashes` 直接收集被审查 `ArtifactEnvelope.payload_hash`，与
   `ApprovalRecord.artifact_hashes` 共享 canonical payload hash 口径；不创建二次 review hash。
2. Review envelope 状态由结构化审查结论推导：`pass -> ready`，`blocked -> blocked`，纯
   `not_checked`/缺参 -> `missing_inputs`，其余待修订错误 -> `failed`。
3. 新 `CalcPackage.supersedes_artifact_id` 明确声明旧计算产物过期。任何仍引用该产物的
   `DesignPackage` 或 `DrawingPlan` 生成 `stale_calculation_used`，责任人为 `hydraulic`。
4. DrawingPlan 的 `integration_conflicts`、`missing_inputs` 与 DrawingPackage 的
   `pipes_reviewed == 0` 均保留为可回溯 evidence；未执行管段审查绝不渲染为合规。
5. 路由继续只读 `ReviewIssue.owner` 的固定四值枚举，按
   `hydraulic -> design -> drawing -> human` 选择单一主责任方；message、object_ref 与
   evidence 不参与路由。
6. Review Agent 不接入 ToolRegistry、ProviderGateway、MCP、文件写入或发布接口。

## 验收

- Review hash 与 ApprovalRecord 真实绑定相同；
- stale calc、空审查对象、not_checked、零管段审查、多 owner 顺序与无写权限均有离线行为测试；
- 审查逻辑保持纯函数，数值仍只来自既有程序化产物。

## 残余限制

- Review 只报告已有结构化证据，不能替代人工审批或在缺少真实图纸样本时声称工程质量通过。

25.46 m/s，水力 Agent 的 envelope `assumptions=[]`，审查同样 pass；人工批准只看到一个哈希。

   `p3_<P3 rule_id>`，`owner=human`（图纸按设计产物确定性生成，派回设计/出图 Agent 只会空转到
   修订上限），正式条文 `error`、非正式/工程惯例 `warning`，正文用 P3 `rendered_finding`
   （等级前缀不得丢）。按路由规则运行停在 `waiting`，需人改输入。
8. **带条件进入人审的披露项**写进新字段 `ReviewPackage.disclosed_limitations`，不参与 decision：

   final package hash 上。
9. **关键未检查项不变**：产物缺失、回读不可判定、`pipes_reviewed == 0`（零管段审查）等仍进
   `not_checked`，照旧阻止 pass（决策 4 现在真正生效）。
