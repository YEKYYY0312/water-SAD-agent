## 0. 增量范围与前提

| 项 | P4.5 新增事实 |
|---|---|
| 形态 | 单机 CLI/harness 仍无 HTTP 服务；新增 `MultiAgentProjectState` 独立状态（不立即膨胀 `WaterAgentState`），经适配节点与主图交换摘要 |
| 产物 | `ArtifactEnvelope`（`artifact_id / artifact_type / schema_version / producer / revision / parent_artifact_ids / payload_hash / status`）包裹 `CalcPackage / DesignPackage / DrawingPlan|Package / ReviewPackage / ApprovalRecord / FinalProjectPackage`；全部 `extra="forbid"`，浮点有限，枚举响亮失败 |

| 开关 | P4.5 默认关闭，`--flow multi-agent` / `WATER_AGENT_FLOW=multi-agent` 显式启用，未启用时旧路径不变 |

## 2. 增量信任边界

在 P2.5 的 B0–B6 之上新增：

```
B7 多 Agent 产物面（可信度取决于血缘与哈希，不取决于"哪个 Agent 说的"）
  ArtifactEnvelope.*  ← 运行时计算与校验，非模型填
  calc_case_id / source_id / segment_id  ← 结构化引用，断链即 blocked

B8 编排器控制面（可信）
  MultiAgentOrchestrator: 顺序 / 路由 / 重试上限 / HITL / 失效传播 / 发布门
  ToolRegistry 最小视图分发（per-stage）

B9 绘图执行面（受控副作用）
  DrawingPlan → staging 草图 → 回读验证 → 批准后 final（窄适配器，路径装配期注入）
```

**边界规则（P4.5 新增，Step 28 起强制）**：

- ✅ `SourceTag.TOOL_OUTPUT / RETRIEVED_FILE / RETRIEVED_CLAUSE` 永不提升为 `SYSTEM_POLICY / USER_MESSAGE`（含 MCP 返回与图纸 TEXT/MTEXT）。
- ✅ 模型不能设置 `artifact_id / payload_hash / approval / release` 状态与真实文件路径。
- ✅ `ReviewIssue.owner ∈ {hydraulic, design, drawing, human}` 是路由唯一输入，自由文本不参与责任推断；多 owner 按 `hydraulic → design → drawing → human` 依赖顺序串行处理。
- ✅ 工具最小暴露：编排器按阶段分发 `ToolRegistry` 视图，Agent 不各自新建 Principal；`Capability.MCP_INVOKE` 仍需 `allow 白名单 + 主体显式授予` 两把钥匙。
- ✅ 无真实坐标/底图时只出 `drawing_class=schematic` 并进图签与最终报告，不得推断穿墙/标高/碰撞。

## 3. 新增 STRIDE × LLM 风险

### T12 跨产物血缘断裂 / 过期计算沿用 — High（P4.5 首要）

- **向量**：Design/Drawing 引用已 `superseded` 的 `CalcPackage.calc_case_id`；`parent_artifact_ids` 指向不存在的 `artifact_id`；`source_ids` 指向未检索条文；`segment_id` 在 Design↔Drawing 间不一致；设计改 `flow/直径/长度/坡度/粗糙系数/水头` 后未触发重算而沿用旧数值。
- **影响**：A10/A4/A3 — 数值与引用失真仍进入设计书与图纸，追溯链断裂后无法回答"哪个数字来自哪次工具调用"。
- **控制（确定性，不依赖 LLM 判断）**：
  - `contracts.py`：`payload_hash` canonical、`extra="forbid"`、枚举/浮点校验；`status` 由编排器确定。
  - `provenance.py`：stale 传播（§0 表）、`supersedes_artifact_id` 链、`calc_case_id / source_id / segment_id` 解析与断链即 `MULTI_PROVENANCE_INVALID / MULTI_RECALC_REQUIRED`。
  - `routing.py`：结构化字段比较判定重算（任务书 §7.2 字段表），不让 LLM 以"影响不大"跳过。
  - 检测器：`stale_calculation_used / provenance_gap / revision_loop_exhausted / contradictory_project_success`（Step 15 扩展）。
- **残余**：需测试覆盖全部失效组合；P0 真实图纸样本缺失时 `project_coordinates` 闭环仍 blocked。

### T13 审批漂移与未授权发布 — High

- **向量**：批准后任一产物 `revision/payload_hash` 变化仍用旧 `ApprovalRecord` 发布；未生成 `ReviewPackage` 即请求审批/发布；`not_checked` 含关键项仍 `pass`；MCP/图纸返回的文本被当成"改路由/改路径/改批准"指令。
- **影响**：A11/审计 — 未授权文件外发，责任不可追溯。
- **控制**：
  - 整体批准绑定（Q4）：`ApprovalRecord.artifact_hashes` 含全量产物 hash，任一变化旧批准失效（`MULTI_APPROVAL_STALE`）。
  - `release_gate`：发布前重算全量 hash，不一致即 `MULTI_APPROVAL_STALE` 不写文件；`MULTI_APPROVAL_REQUIRED / MULTI_REVIEW_REJECTED / unapproved_export` 结构化拒绝。
  - 窄适配器 `drawing_executor.py`：模型只给 `output_file_id`，真实 `staging/final` 路径装配期解析；`human_confirmation=true` 的 MCP 工具在 `confirmation_handler_ready=false` 时整台不暴露（Step 26 才转 interrupt）。
  - `SourceTag` 不可提升 + 产物文本仍过输入/输出护栏（规则集 `p2.5-step14-2026-09-06`，确定性正则）。
  - 检测器：`reviewer_bypassed / unapproved_export / approval_drift`。
- **残余**：`confirmation_handler_ready` 翻转与 HITL `interrupt→resume` 需 Step 33 实测；告警投递仍 `local_event_only`。

### T14 绘图冒充正式图 / 坐标幻觉 — Medium-High

- **向量**：无底图/坐标时推断真实穿墙/标高/碰撞；`$INSUNITS` 缺失或 `unitless`；标注 `DN/材质` 与 `DesignPackage` 不一致；`DrawingPlan` 与 `DesignPackage` 的 `segment_id/DN/材质/系统/长度` 逐项不一致仍产正式候选；MCP 返回文本改图层/坐标。
- **影响**：A12 — 示意图被误作施工图，尺寸与系统错。
- **控制**：
  - `DrawingPlan` 是唯一事实源：`kind ∈ {line, polyline, text, mtext}`（P3 已能回读子集），`$INSUNITS` 显式，无坐标只出 `schematic` 且进图签与最终报告；标注字段只能从 `DesignPackage` 注入；`integration_conflicts` 非空时不产正式候选（`MULTI_DRAWING_CONFLICT / MULTI_DRAWING_UNAVAILABLE`）。
  - 路径不进 schema，DXF 经 `ezdxf` 产出后必经 `read_drawing → map_pipes → review_drawing` 回读，`roundtrip_segment_recall == 1.00` 才算 Step 31 闭环（Q1）。
  - P1 扩展 INSERT/ARC 前必须先扩 P3 读图端与 gold，并重标 `ANNOTATION_MATCH_RADIUS`。
  - 检测器：`contradictory_project_success`（`blocking issue / not_checked` 仍 `succeeded`）。
- **残余**：真实 `project_coordinates` 闭环需脱敏真实 DXF 底图（P1）；`ANNOTATION_MATCH_RADIUS` 未重标定前不得声称真实召回率。

## 6. 复核节奏（增量）

- 每次新增产物字段、枚举值、失效因子、错误码、图阶段：先更新本文档 + `p4.5-step-27-decision.md` + `p4.5-tool-matrix.md`，再改 `contracts.py / provenance.py / routing.py`（覆盖测试会挡住反序）。
