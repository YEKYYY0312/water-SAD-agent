# React 前端设计（P5）

## 1. 核心定位

前端是 Agent 与工程师工程师之间的**交互面 + 信任面**。给排水工程师信任一个 Agent 的前提是**能看到它在做什么、引用了哪条规范、算出了什么**。因此前端不只做聊天框，还要做「透明化」和「可追溯」。

## 2. 界面模块

```
┌──────────────────────────────────────────────────────┐
│ 左侧: 会话列表            中间: 对话区          右侧: 面板│
│  (历史/项目)              │ 用户消息+文件       │ 工具调用树│
│                          │ Agent 回复        │ 规范引用 │
│                          │                  │ 图纸预览 │
│                          │                  │ 计算卡片 │
│                          └──────────────────┴─────────┘
│  底部: 输入框 + 文件上传(拖拽) + 一键反馈(👍/👎)        │
└──────────────────────────────────────────────────────┘
```

## 3. 关键交互能力

| 能力 | 说明 |
|---|---|
| **流式对话** | SSE / WebSocket 流式输出，打字机效果 |
| **文件上传** | 拖拽上传 PDF/Word/Excel/DWG；上传即解析，预览解析结果 |
| **工具调用可视化** | 实时展示 Agent 调用了哪些工具、检索了哪些条款（折叠树） |
| **规范引用卡片** | 每个引用渲染为卡片（规范号 + 条号 + 条文），可点击看原文 |
| **计算卡片** | 水力计算结果用结构化卡片展示（参数、公式、结果、单位） |
| **图纸预览** | DWG 转图预览（P3），标注审查发现的缺陷位置 |
| **一键反馈** | 回答差评 → 回流到评测集（harness 数据飞轮） |

## 4. 技术选型

| 项 | 选型 |
|---|---|
| 框架 | React + TypeScript + Vite |
| 状态 | TanStack Query / Zustand |
| 流式 | 原生 SSE / path-to-regexp / @microsoft/fetch-event-source |
| 聊天 UI | 自研或 shadcn/ui + streaming 组件 |
| 图纸预览 | CAD 转 SVG/PNG（如 Autodesk Viewer 或自研转换）|

## 5. 前端 → 后端 API 约定

```
POST /api/chat           # 发消息（流式SSE返回 token + 工具事件）
POST /api/upload         # 上传文件 → 解析，返回解析摘要
GET  /api/tools          # 列出当前挂载的 MCP/工具
GET  /api/spec/:ref      # 取规范条款原文（用于引用卡片）
POST /api/feedback       # 上报反馈（好坏、原因）→ 入库评测集
GET  /api/run/:id/trace  # 取一次 run 的 trace（透明化）
```

## 6. 设计原则

1. **先透明后美观**：工具调用可视化 / 引用卡片必须先于视觉打磨。
2. **反馈即数据处理飞轮**：前端反馈直接对接 harness 数据回流。
3. **工程可读**：给排水工程师要看参数、单位、规范 —— 卡片要结构清晰、单位明确。
