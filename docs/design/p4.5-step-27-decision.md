## 0. 最重要的结论（先说）

1. **四 Agent + 确定性编排器定版**：`hydraulic / design / review / drawing + MultiAgentOrchestrator（LangGraph 状态机）`。协作形态为**结构化流水线 + 有界责任回流**，不做四模型自由群聊；Agent 之间只传 `ArtifactEnvelope`（Pydantic `extra="forbid"`），不传完整消息历史，不直接调用彼此，由编排器按 `ReviewIssue.owner` 枚举确定性路由。
2. **Q1–Q6 全部拍板**：P0 以二维 `schematic DXF` 为最小闭环（Step 31 必须完成 `DrawingPlan → DXF → read/map/review → gold` round-trip，才算闭环；不声称施工图）；循环上限按任务书 §6.4 冻结（`24 / 2 / 2 / 2 / 3`）；设计 Agent 首版从"给水/排水管段"扩大到立管/洁具连管/水泵连管/消防管段的**管段抽象**（设备选型仍为 `unresolved_items`）；发布为**整体批准**（`FinalProjectPackage` 全量 hash 绑定）；P4.5 默认关闭，经 `WATER_AGENT_FLOW=multi-agent` + CLI `--flow multi-agent` 显式启用；威胁模型增量**新建独立文档** `p4.5-threat-model-increment.md` 并在原威胁模型加引用。
3. **权限无新旁路**：四 Agent 不是 Principal，不各自新建认证面；沿用 `Principal.local(thread_id, capabilities=...)` + `ProviderGateway` + `ToolRegistry.invoke → GuardrailPipeline` 单一治理链路；编排器为每阶段提供**最小 ToolRegistry 视图**（见 §3），`Capability.MCP_INVOKE` 仍需 `allow 白名单 + 主体显式授予` 两把钥匙；`ToolSpec.description` 投毒防御、`inputSchema` 确定性子集、`SourceTag` 不可提升三条纪律不变。
4. **Step 27 零代码**：本步不建 `src/water_agent/multi_agent/`，不改 `WaterAgentState`（P4.5 先用独立 `MultiAgentProjectState`，通过适配节点与主图交换摘要），不新增 Provider 出口，不改变默认 CLI 行为（`qa`）。
5. **真实施工图/DWG/Revit/规范现行性仍为 blocked**（任务书 §17），P0 不以合成测试替代实机验收；任何"已具备施工图交付"的说法都是错的。

## 1. Q1–Q6 决策（与任务书 §19 一一对应）

### D1 Q1 — P0 绘图闭环形态

- **决策**：接受任务书 §9.1 P0 口径 —— P0 仅承诺**二维给排水系统草图/示意图**（`LINE / POLYLINE / TEXT / MTEXT` + 显式 `$INSUNITS` + `drawing_class=schematic` 图签），由 `DrawingPlan` 唯一驱动、经 `ezdxf` 产出、必须被现有 `read_drawing → map_pipes → review_drawing` 回读且与 `DesignPackage` 逐项一致才算闭环。
- **你的答复**："q1 线不接受，我们需要 step31 闭环" — 落为：不接受"只画线就视作完成"，**Step 31 必须以 round-trip 闭环为验收**（`roundtrip_segment_recall == 1.00`），不闭环不得进入审查与批准。P0 不承诺 DWG 直写、不承诺 INSERT/ARC/XREF、不推断真实建筑坐标；缺底图/坐标时只能出 `schematic`，不得冒充 `project_coordinates`。
- **为什么**：P3 基线仍为 DXF，真实设计院图纸样本与半径标定尚未完成（§17.2）；先扩写图端而不扩读图端会导致"产出不可验证"。

### D2 Q2 — 循环上限

- **决策**：按任务书 §6.4 冻结并版本化：`MAX_MULTI_AGENT_STEPS=24`，`MAX_HYDRAULIC_REVISIONS=2`，`MAX_DESIGN_REVISIONS=2`，`MAX_DRAWING_REVISIONS=2`，`MAX_REVIEW_ROUNDS=3`。超限 `blocked + MULTI_RETRY_EXHAUSTED`，禁止继续调用模型。
- **你的答复**：接受。阈值进版本化配置，调整时必须改配置版本 + 测试 + baseline。

### D3 Q3 — 工程设计 Agent 首版范围（扩大）

- **决策**：从任务书 §19.3 默认"仅给水/排水管段"**扩大**为：给水、排水、立管、洁具连管、**水泵进出管**、**消防给水管**的**管段抽象**均纳入 `DesignPipeSegment`。
- **你的答复**："都要，进行扩大"。
- **契约影响（Step 28 落）**：
  - `DesignPipeSegment.system` 枚举从 `water_supply | drainage` 扩为 `water_supply | drainage | fire_protection`（洁具/水泵连管归属给水系，立管以 `start_node/end_node` 高程差表达，不新增实体类型）。
  - `ProjectBrief.systems` 同步扩枚举；`HydraulicCaseRequest` 的公式口径仍以 `tools/hydraulics.py + graphs/calc.py` 现有内核为准，内核不支持的工况（水泵特性曲线、消火栓/喷淋水力计算细则）**不得由 LLM 自算**，必须进 `missing_inputs / unresolved_items / recalculation_requests` 并阻断 `verified`。
  - 洁具额定流量/当量、水泵选型、消防分区/危险等级等**设备/系统级选型**首版仍为 `unresolved_items`，不得静默默认；这是"管段抽象扩大、设备选型仍 blocked"的分层口径。
- **代价**：`ma-contracts` 的枚举与校验、`ma-hydraulic` 的公式路由、`ma-design` 的缺参阻断、`ma-eval` 的合成 gold 均需同步扩，Step 30 验收对 `not_verified` 的断言更严。

### D4 Q4 — 发布批准粒度

- **决策**：采用任务书默认**整体批准** — `ApprovalRecord.artifact_hashes` 绑定 `calc / design / document / drawing / review` 全量 `payload_hash`，任一产物 `revision / payload_hash` 变化旧批准自动失效（`MULTI_APPROVAL_STALE`）。
- **你的答复**：同意。
- **为什么**：分产物批准会引入 partial release 与依赖失效的额外状态机（例如 design 已变但 drawing 仍用旧批准发布），P0 先收敛为整体原子发布。

### D5 Q5 — 特性开关与默认行为

- **决策**：P4.5 默认关闭，显式启用。CLI `--flow multi-agent` 与环境变量 `WATER_AGENT_FLOW=multi-agent` 双入口等价；harness 以 `suite.json: flow: "multi-agent"` 启用；未启用时旧 `qa / docgen / drawing_review` 路径行为不变（`P0_ACCEPTANCE` 与 `scripts/ci_gate.sh` 不受影响）。
- **你的答复**：可以。
- **接线时机**：Step 33 才接 `orchestrator + SqliteSaver interrupt/resume + 窄导出适配器`，Step 27 仅冻结开关口径，不写分支代码。

### D6 Q6 — P5 前端时机与威胁模型落盘位置

- **决策**：确认任务书 §19.5 — **Step 34 后再接 P5 前端**（展示四 Agent 阶段、问题责任人、审批产物哈希）；威胁模型增量**按推荐新建** `docs/design/p4.5-threat-model-increment.md`，并在 `docs/design/p2.5-threat-model.md §6` 追加引用，不直接膨胀原文件。

## 3. 能力地图与工具矩阵（定版，详见 `p4.5-tool-matrix.md`）

### 3.1 建设顺序（依赖单向，Agent 间不直接调用）

```
ma-contracts → ma-hydraulic → ma-design → ma-drawing → ma-review → ma-orchestrator → ma-eval
```

### 3.2 四 Agent 最小工具视图（编排器按阶段提供，非 Agent 自选）

| Agent | 可见工具 | 不可见工具 | 依据 |
|---|---|---|---|
| hydraulic | `calc_velocity`（`Capability.CALCULATE`）+ 参数解析（只读） | `retrieve_clauses / cite_clauses / material_stats / read_drawing`、全部 MCP、文件写入/最终发布 | 任务书 §4.1/§8.1：禁止编造缺参、直接写设计、直接绘图、引用未检索条款 |
| design | `retrieve_clauses / cite_clauses`（`RETRIEVE_CLAUSES / CITE_CLAUSES`）+ `material_stats` 只读预检 | `calc_velocity`、全部 MCP、文件写入/最终发布 | §4.2：禁止自算水力、改 `CalcPackage`、编造 `source_id`、静默默认材质/系统/单位 |
| review | `cite validator / docgen self-check / drawing read→map→review` + `stale / provenance / not_checked` 检测器（只读） | 全部写工具、MCP 危险工具、设计修改 | §4.3/§8.1：只读审查，无写能力；`owner` 枚举是路由唯一输入 |
| drawing | `material_stats` 聚合 + `docgen` 模板 + `DrawingPlan` 渲染 + 草图执行窄适配器 + `read_drawing` 回读 | `calc_velocity`、任意 MCP 水力重算、未授权路径、直接最终发布 | §4.4/§8.3：`DrawingPlan` 是唯一事实源；路径不进 schema；批准前不发布最终文件 |

治理不变式：全部工具调用经 `ToolRegistry.invoke → GuardrailPipeline.validate_tool_call`（能力/路径/域名/注入/大小）；6 个远程出口经 `ProviderGateway`；`ToolSpec.description` 注入检测 + `inputSchema` 确定性子集 + `SourceTag` 不可提升；MCP 工具名 `mcp_<server>_<tool>`（≤41 字符，超长截断+8位哈希）仅在 `allow` 放行时占 schema token。

## 5. 已知限制与 blocked（Step 27 重申，与任务书 §17 一致）

1. 真实施工图质量 blocked：P0 仅 schematic + 合成 round-trip。
2. 真实设计院图纸召回率 blocked：缺真实样本，INSERT/XREF 未覆盖。
3. DWG/真实 Revit blocked：需 ODA/Windows/Revit/pyRevit（Step 26）。
4. 正式规范引用 blocked：`data/versions.json` 人工核实前不得写"现行有效"。
5. 工程设计质量认证 blocked：合成测试不替代注册工程师复核。
6. 无底图/坐标时只出 `schematic`，不得推断空间位置与碰撞。
7. 多 Agent 不等于并行提速：主链 `hydraulic → design` 强依赖顺序，成本可能高于单 Agent。
8. 护栏为确定性正则，必然存在未覆盖变体，安全由类型契约 + 最小暴露 + 权限 + HITL + 产物验证共同收敛。
