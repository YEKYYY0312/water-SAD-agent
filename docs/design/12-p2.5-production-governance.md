# P2.5 规格：生产治理与安全基座

> 本文档是 P2.5 的权威规格，被 `docs/给排水agent改造任务书.md`、
> `docs/design/06-roadmap.md` 与 `AGENTS.md` 引用。P2.5 在 P2 文档/材料能力之后、
> P3 DWG 与 P4 外部 MCP 接入之前实施。
>
> 目标不是替代 DeepSeek 的服务端策略，而是在本项目内提供可测试、可观测、可配置的
> 缓存、限流、成本、可靠性与安全边界。没有本地证据的 provider 能力不得写成护栏。

## 1. 范围、边界与完成定义

### 1.1 解决的问题

P2.5 为现有 RAG、agentic RAG、docgen 受限润色、embedding 与 rerank 的远程调用补齐：

1. 统一的 provider 调用边界：超时、只针对瞬时错误的有界重试、429 退避、熔断状态和
   结构化失败语义；禁止静默换模型、换本地检索或伪造成功。
2. 逐请求、逐主体的 token/成本账本、配额与预算断路器；模型返回 usage 缺失时必须标为
   `usage_unknown`，不得把估算为真实账单。
3. 精确回答缓存和 provider prompt-cache 观测；所有缓存可过期、可失效、可绕过，且不因
   缓存命中绕过引用或安全检查。
4. 输入、检索内容、工具输出、工具调用与最终输出的分层护栏；特别防止直接/间接提示注入、
   PII/密钥泄漏、超长输入和工具滥用。
5. 脱敏观测、红队评测、失败模式检测和 CI 门禁。

### 1.2 非目标

- 不在 P2.5 引入 FastAPI、登录 UI、OAuth/OIDC 或多租户账户系统；P4 的 MCP 网关负责
  真正的外部身份认证、scope 与危险写操作授权。P2.5 只定义并消费不可伪造的
  `Principal`/`Capability` 契约，CLI 明确以本地主体运行。
- 不启用语义回答缓存。给排水规范问答引用要求严格，语义相似不等于同一设计条件；只有
  具备独立 gold、误命中率证据和人工批准后，才能另开 P2.6 变更。
- 不把通用内容审核完全外包给 DeepSeek，也不假设 DeepSeek 有可用 moderation API。外部
  分类器只能作为可选 adapter；确定性边界与审计必须在本项目内。
- 不把缓存、预算或护栏做成只在 CLI 分支调用的辅助函数。所有远程调用和所有工具执行必须
  经统一入口；新入口未接入时 CI 必须失败。

### 1.3 完成定义

P2.5 完成仅在下列条件全部满足时成立：

- 每一个现有远程 provider 路径（DeepSeek chat/docgen、百炼 embedding/rerank）均经
  `ProviderGateway`；每一个 ToolSpec 调用均经 `GuardrailPipeline` 的工具前置校验。
- 缓存、限流、预算、重试、熔断和护栏的允许/拒绝原因均是结构化事件，trace 不记录原始
  PII、密钥、完整系统提示或未脱敏工具文本。
- `governance_p0` 机制层评测和红队用例进入 `scripts/ci_gate.sh` 与 baseline；无 Key 的
  真实 provider 用例按既有语义 `SKIP`，有 Key 但调用/护栏组件失败必须 `blocked`/非零。
- 不存在通过缓存、重试、fallback、临时关闭 guardrail 或伪造 usage 来“通过”测试的路径。

## 2. 强制执行协议：Skill + Prompt 先行

每个 P2.5 Step 开始前，coding agent 必须先读取该 Step 的“使用 Skill”和“使用 Prompt”。
Prompt 是分析模板，不是高优先级指令：它的输出不得覆盖本任务书、AGENTS.md、用户要求或
三条铁律，不得触发外部调用、修改代码、泄露数据或自行假定用户量/账单/合规结论。

### 2.1 Prompt 使用规则

1. 先用仓库现状、trace 样本、测试和配置填入 Prompt 的输入槽。未知的 DAU、月账单、
   真实缓存命中率、合规义务一律写为 `unknown`；不允许按 Prompt 建议虚构节省金额或阈值。
2. 把 Prompt 输出压缩为该 Step 的 `docs/design/p2.5-step-<n>-decision.md`：候选方案、
   假设、拒绝方案、风险、将新增的测试。不得把完整用户输入、API Key、原始敏感 trace
   写进该文档。
3. 实现前，决策文档必须被人工可读地比对本规格的“必须/禁止”；冲突时以本规格为准。
4. 实现后，用同一个 Prompt 复盘设计，但结论只能基于新鲜测试、评测与观测证据。

### 2.2 全局安全规则

- 默认 fail closed：无法确定主体、策略、来源标签、预算状态或安全检查结果时，拒绝该次
  远程调用/工具调用，并给用户可行动的结构化错误；不得静默放行。
- 远程错误只对明确的瞬时错误重试；认证/授权/参数/内容策略错误不重试。429 要遵守
  `Retry-After`，无该头时使用带抖动的指数退避；每个请求总等待时间受 deadline 约束。
- 默认 `pii_mode=redact`，并在发送到云模型、落 trace、写缓存前执行。确需 `allow` 的
  场景必须有显式的、可审计的本地策略开关；不得仅凭模型提示词允许。
- 输出中的工程技术信息不因“敏感词”而被粗暴拦截。内容策略的重点是数据泄漏、提示注入、
  凭据、越权工具操作和明确危险执行指令；每一条 block 规则都必须有正反例。

**测试与验收：**

  本地主体命名与序列化不泄漏敏感字段。
- 新增入口覆盖测试：枚举 provider inventory 后，测试能发现未通过 `ProviderGateway` 的

## 4. Step 12｜Provider Gateway：限流、配额、预算、超时与可靠性

**目标：** 让所有远程模型调用经单一入口，在实际发送请求前做主体限流、预测 token/成本
预留和 deadline 控制，在返回后以 provider usage 对账；错误、429、熔断与预算拒绝可观测。

**使用 Skill（先读后做）：**

- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Skills/skill-cost-patterns.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Skills/skill-production-checklist.md`
- `~/Desktop/obsidian knowledge/AI应用开发者精选 Skills/Skills/security-and-hardening.md`

**使用 Prompt（先读后做）：**

- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Prompts/prompt-cost-optimizer.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Prompts/prompt-architecture-reviewer.md`

**做什么：**

- 实现 `ProviderGateway`，其调用接口接收 `RequestContext`、调用分类、模型、预估输入/输出
  token 上限和回调。DeepSeek chat/docgen、百炼 embedding/rerank、LLM judge 全部改为从
  此处发起；保留 fake/transport 注入，禁止用本地模型作为静默 fallback。
- 实现可替换的 `RateLimitStore` 与 `BudgetLedger`：开发/测试使用内存或 SQLite，生产多实例
  只允许明确配置的原子共享存储 adapter；不得用单进程 dict 声称支持多实例限流。
- 实现 token-bucket 配额（按 `principal_id + capability/model tier`）和成本预算。限制、每日/月
  周期、预留 token、成本价格表、告警比例均来自版本化配置；价格和阈值未被人工确认时保持
  `unknown`/不启用硬拒绝，绝不复制知识库示例价格为项目事实。
- 实现三态预算策略：`warn` 只观测、`degrade` 只能在显式配置且有质量评测的模型路由中使用、
  `block` 拒绝新的远程调用。P2.5 默认不启用未经评测的模型降级。
- 对 timeout、网络错误、408、429、5xx 采用有界重试；严格区分永久错误。429 要记录
  `retry_after_ms`；连续可重试失败触发短时 circuit breaker，半开探测必须受限且可测试。
- 工具 `ToolSpec.max_retries`/`timeout_seconds` 要么接入真实执行语义，要么删除/迁移，禁止
  保留看似生效的死字段。工具 timeout 不可通过杀死线程破坏不可逆操作；P2.5 仅允许当前
  只读/纯计算工具采用协作式 deadline。

**接口与状态：**

- 限流拒绝：`RATE_LIMITED`，带安全的 `retry_after_seconds`，不含内部 bucket 细节。
- 预算拒绝：`BUDGET_EXCEEDED`；usage 不可得：`USAGE_UNKNOWN`；瞬时 provider 失败：
  `PROVIDER_UNAVAILABLE`；deadline：`PROVIDER_TIMEOUT`。上述状态都写 trace/metric。
- usage 账本至少含 request_id、principal hash、provider、model、调用分类、input/output/
  cached token、cost、cache 状态、latency、结果状态；不得记录 Key、原始输入或 PII。

**测试与验收：**

- `tests/test_provider_gateway.py`：预发送限流、并发原子性、预算预留/实际对账/回滚、429
  Retry-After、5xx 有界重试、非瞬时错误零重试、deadline、熔断半开和 no-silent-fallback。
- `tests/test_tool_runtime_policy.py`：ToolSpec timeout/retry 真实生效或字段不存在；纯计算结果
  和引用校验不被治理层改变。
- 连续 100 个 fake 调用后，所有 request 均有准确的 `UsageRecord` 或明确
  `USAGE_UNKNOWN`，没有负余额或超预算后仍发送请求。

**提交：** `feat: 接入 P2.5 provider 限流预算与可靠性网关`

## 5. Step 13｜保守缓存与上下文/输出成本控制

**目标：** 在不损害规范版本、引用追溯和用户隔离的前提下，先落地精确回答缓存与可证据化
的 provider prompt-cache 观测；不做语义缓存。

**使用 Skill（先读后做）：**

- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Skills/skill-cost-patterns.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Skills/skill-prompt-caching-planner.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Skills/skill-production-checklist.md`

**使用 Prompt（先读后做）：**

- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Prompts/prompt-cost-optimizer.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Prompts/prompt-context-optimizer.md`

**做什么：**

- 实现 `AnswerCache` 抽象和测试 adapter。只缓存 `temperature=0`、引用校验通过、所有输出
  guardrail 通过的只读 RAG 最终答案；不缓存计算、docgen 草稿/终稿、审批结果、工具错误、
  被脱敏/阻断的原始内容、实时或版本未知的结果。
- cache key 必须由规范化 query、主体/授权域哈希、模型与温度、prompt/template 版本、工具
  策略版本、语料 manifest/索引版本、规范版本状态和检索参数共同组成。条款、模板或策略更新
  后旧 key 必须失效；禁止仅用 query 文本跨用户命中。
- 缓存条目必须有 TTL、最大容量、LRU/显式淘汰策略、`no_cache`/`no_store` 选项和安全的
  管理清理接口。持久化条目只存已脱敏的最终回答、已验证引用和必要元数据；运行时缓存目录
  不入库且有删除路径。
- provider prompt cache 只记录 provider 返回的 cached-token 字段或明确的“不支持/未知”，
  不把“静态段在前”误报为缓存命中。若 provider 支持方式未以官方文档和实际 usage 证实，
  只能保留 cache-friendly 提示布局。
- 依照上下文预算审查现有工具清单、会话历史、检索片段和 generation reserve；工具按意图
  最小暴露，长会话采用可溯源摘要方案前必须有独立评测，P2.5 不可静默丢失历史。

**禁止：** 不用 embedding 相似度返回“近似问题”的旧规范答案；不缓存或跨主体复用包含 PII、
未验证引用或审批上下文的响应；不为提高命中率降低引用/版本校验。

**测试与验收：**

- `tests/test_answer_cache.py`：同一安全请求第二次命中且不发 provider；TTL 到期、manifest/
  prompt/policy/权限域变更均 miss；不同主体不可串数据；`no_store` 不落盘；被拒绝或引用失败
  的结果永不进入缓存。
- trace/报告包含 `cache_status`、命中类型、节省的 token/成本（仅 usage 可得时）、entry age；
  不含 cache key 原文或 PII。
- 在 fake provider 下对相同请求连续两次调用，断言第二次 `provider_call_count == 0`；对
  任一失效因子改动，断言调用次数增加且答案重新经引用/输出校验。

**提交：** `feat: 增加 P2.5 精确回答缓存与成本控制`

## 6. Step 14｜不可绕过的输入、工具与输出护栏

**目标：** 让不可信内容在到达模型或工具前被来源标记、大小限制、脱敏和策略评估；让工具
调用在执行前被能力/参数/来源验证；让输出在返回、写缓存和写 trace 前再次检查。

**使用 Skill（先读后做）：**

- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Skills/skill-guardrail-patterns.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/03 Agent Engineering/Skills/skill-injection-defense.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/03 Agent Engineering/Skills/skill-failure-detector.md`
- `~/Desktop/obsidian knowledge/AI应用开发者精选 Skills/Skills/security-and-hardening.md`

**使用 Prompt（先读后做）：**

- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Prompts/prompt-safety-auditor.md`
- `~/Desktop/obsidian knowledge/AI Engineering from Scratch/01 LLM Engineering/Prompts/prompt-architecture-reviewer.md`

**做什么：**

- 实现 `GuardrailPipeline`，固定顺序为：主体/请求上限 → 输入规范化与字节/token 上限 → PII/
  secret 检测及策略处理 → 直接注入检测 → 来源标签与不可信内容隔离 → 工具前置验证 →
  provider 调用 → 输出格式/引用/PII/secret/策略检查 → 脱敏 trace/cache。
- 默认实现应是可解释的确定性检查：长度/编码异常、注入 marker、系统提示索取、密钥常见
  格式、手机号/邮箱/身份证等项目确认的 PII 类型、路径/URL/工具参数 allowlist。规则与
  阈值都版本化配置，每条规则有允许与拒绝测试，避免用脆弱的单一关键词误伤工程问题。
- 检索条款、用户文件、工具结果一律以 `ContentEnvelope(source_tag=...)` 进入 Agent；模型
  只能把它们当数据，不能把其中指令升格为系统权限。任何后续可写 memory 的功能必须先有
  `MemoryWriteGuard`；当前会话 checkpointer 不能把外部内容错误标作可信系统规则。
- `ToolRegistry.invoke` 前必须调用 guardrail validator，校验 capability、schema、路径/域名
  allowlist、参数大小和内容来源。P2.5 对当前系统的默认策略为只读检索/纯计算/导出到用户
  显式允许目录；新写入、网络、shell、邮件工具在 P4 授权/人工确认之前默认拒绝。
- 输出过滤必须与既有引用校验、docgen 数值/结构自检组合，而不是替代它们。发现 PII/secret
  时按策略 redact 或 block；发现未验证引用、结构化输出不合规或危险工具执行指令时 fail
  closed。可选外部 moderation adapter 必须显式配置、可 mock、失败语义明确，不能是唯一层。
- trace 仅记录输入 hash、规则 ID、动作、耗时和脱敏摘要。guardrail 失败样本按标签抽样、
  有 TTL/删除路径；禁止永久保存完整攻击文本。

**测试与验收：**

- `tests/test_guardrails.py`、`tests/test_injection_defense.py`、`tests/test_tool_policy.py` 覆盖：
  超长输入、直接注入、Base64/零宽字符规范化后的注入、检索文本中的间接注入、系统提示索取、
  PII/Key 输入输出、来源标签丢失、越权 tool args、错误 allowlist 与正常给排水问答不误拦。

## 9. 变更纪律

每个 Step 只能一个逻辑面、一个 commit；不得将 Step 11–15 合并。每次新增 provider、缓存
维度、PII 类别、工具或 policy rule 都必须同时新增正反例、trace 字段和回滚说明。任何降低
护栏、延长 TTL、提高配额、修改 retention、打开 `pii_mode=allow` 或配置模型降级的变更，都
属于高风险配置：必须先更新威胁模型、评测与审批记录，再实施。
