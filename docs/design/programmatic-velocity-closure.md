# 纯流速计算的确定性零引用收口

2026-11-06，用户批准在现有桌面分支实现。问题证据：`docs/evals/macos-real-model-2026-11-06.md`，工具返回 1.132 m/s，最终因零引用失败。

## 契约

不是豁免 LLM 自由生成的数值或规范结论，而是把严格限定的计算请求投影成程序化结果摘要。当前仅支持单次 canonical `calc_velocity_spec`，不建立通用计算插件协议，不改公式、场景阈值、Prompt、工具 schema、规范引用规则或基线。

1. 适配器仅在 canonical ToolSpec 通过唯一执行入口 `ToolRegistry.invoke` 成功执行后生成本地 artifact receipt；receipt 不进入模型输入，工具正文保持原形。按工具对象身份识别，外部同名工具或正文伪造无效。
2. 用户明确给出内径 mm、流量 L/s 和满管流速计算意图。删除这些参数及有限的计算表达后，只允许标点和列明的礼貌／前提表达；未知剩余文本、DN 而无内径、非满管、额外任务或参数歧义均不豁免。仅支持普通十进制与列明单位，不猜单位／工况。
3. 仅本轮一个 AI 工具调用和一个对应成功结果，id／名称／参数／receipt／结果严格一致；终答在工具结果之后且有可替换的消息 id。失败、非有限值、bool、非空 assumptions、其他调用／检索／引用、历史证据均不适用。
4. D/Q 必须与用户明示数值一致。终答由固定模板只渲染工具参数 D/Q 与结果 v，不转发 LLM 自由正文、场景限值或合规判断；说明仅做满管计算、未进行规范符合性判断。模型补入的默认 scenario 不作为用户已提供用途。
5. 同 id 替换最终 AIMessage，warning `no_citation_programmatic_calculation` 显示此收口路径。finalize 仍执行原输出护栏并持久化最终状态；网址校验读取替换后的正文。空回答不因已有工具结果而成功。

## 实施与验收

- 先写适配器及真实图回归，复现失败，再实现 receipt、资格检查／渲染及 validator 接线。
- 反例覆盖混合任务、伪造工具、错参数／id、重复／失败结果、前轮证据、未知单位、非空假设及规范问答；真实 checkpoint serde 保存改写后的正文。
- 独立审查方案和实现，执行相关测试、完整 ci_gate、前端与桌面验证，不改入仓基线。
- 构建 App/DMG，保留旧包与用户数据，替换实际安装路径；用同一问题做修复后的单次真实验证，保留前次失败不覆盖；验证原生最终状态、重启与 Word 保存。旧 8000/8001 服务不动，不读取或转移现有模型密钥。

限制：这是有限语法的流速计算收口，不证明任意自然语言计算／规范混合任务都能识别。此前凭据日志审计缺口不因本修复消失。
