# P4.5 Step 31 决策记录：DrawingPlan staging 与 P3 回读闭环

**日期**：2026-09-11
**状态**：Implemented
**范围**：P4.5 Step 31 的 DrawingPlan、P0 DXF staging、docgen/materials 适配；不改变旧
`qa`、`docgen`、`drawing_review` 路径，也不新增图纸解析、映射或规则实现。

## 结论

1. Drawing Agent 只生成无路径的 `DrawingPlan`。实际 staging 目录与 DXF 路径仅由
   `drawing_executor.stage_drawing_package()` 在装配期注入，且不进入 Agent schema 或
   artifact payload。
2. `length_m` 缺失、DN 缺失、材质缺失或不支持的 `$INSUNITS` 都是
   `missing_inputs`。不得以 `10.0m`、默认材质或默认单位产生图元。
3. 有 `integration_conflicts`、非 `ready` 上游产物或断开的 Design→Calc parent 链时，
   不渲染 DXF。结果是结构化 `blocked` 的 DrawingPackage，`staged_file_id=None`。
4. `PlannedEntity` 记录并校验 `source_artifact_id`，且 P0 图元必须指向
   `DrawingPlan.source_design_artifact_id`。带 `segment_id` 的图元还携带来自
   DesignPackage 的 `system`、`dn_mm`、`material`，用于逐项核对。
5. 只有 executor 已确认文件存在、可读、`read_drawing → map_pipes → review_drawing`
   完整执行、单位一致、无字段差异且 `roundtrip_segment_recall == 1.0` 时，
   DrawingPackage envelope 才能为 `ready`。

## 实现边界

- 单位换算复用 `drawing.mapping.metres_per_drawing_unit()`；DrawingPlan 坐标按明确的
  `$INSUNITS` 表示，P3 映射回读后保留设计长度。`unit_known=False` 时 P3 的
  `MappedPipe.length_m` 继续为 `None`。
- executor 不复制 P3 的解析、映射或审查规则；它只调用既有实现并把可验证的回读结果
  包进 DrawingPackage。
- docgen 适配调用 `docgen.templates.render_docgen_doc()`；材料适配调用
  `materials.core.aggregate_materials()`。当现有材料契约不能表达完整设计（例如当前
  material stats 不接受 `fire_protection`）时，`DrawingPlan.output_adaptations.materials`
  明确返回 `status=blocked` 与问题清单，不产生部分材料总量冒充完整清单。

## 验收证据

- 缺长度、未知单位、stage 文件不存在、DXF 字段篡改、segment/DN/material/system 不一致、
  上游冲突禁止落盘均有离线行为测试。
- `roundtrip_segment_recall` 由实际 P3 回读计算；零管段按 `0.0` 处理，绝不预置为 `1.0`。

## 残余限制

- P0 仍仅是 LINE/POLYLINE/TEXT/MTEXT 合成 DXF schematic；真实设计院 DXF、INSERT/XREF
  与真实图纸召回率验收仍 blocked。
- DrawingPackage 的 `ready` 仅说明 P0 staging 闭环成立，不代表已人工批准或已发布最终文件。
