# Harness Engineering —— 评测框架

评测（Harness）是给排水 Agent 可靠性的根基。目标：**每次改动（prompt / 模型 / 工具 / 检索）都能自动跑分，防止退化**。

## 1. 分层评测金字塔

```
        任务级（端到端）： 完整任务成功率, 成本$, 延迟ms
        组件级：         检索 recall/precision, 工具调用正确率
        单元级：         水力计算数值准确率（程序化判分）
        回归：           每次改动全量跑, 对比基线
```

| 层级 | 评测对象 | 金标准评测集 | 指标 | 判分方式 |
|---|---|---|---|---|
| 单元 | 水力计算工具 | 已知答案案例（DN150、Q=20L/s → v=?） | 数值误差 | **程序化数值比对**（阈值 ≤1%） |
| 组件 | 检索 | 规范问答 gold 对 | recall@k、precision、条款命中率 | 程序化（比对检索到的条款） |
| 组件 | 意图路由 | 意图标注集 | 分类准确率 | 程序化（对比 label） |
| 任务 | 端到端 | 场景任务（"算某建筑生活给水立管管径"） | 成功率、成本、延迟 | LLM-judge + 人工 |
| 反射 | 合规/引用 | 含陷阱失败用例 | 引用正确率、幻觉率 | LLM-judge + 程序化 |

## 2. 判分策略（关键原则）

- **计算类一律程序化判分**：不请 LLM 判断对错，用真实公式算出 gold 值，比对误差。
- **规范问答用 LLM-as-judge + 人工标注**：因为答案的「正确性」依赖语义，但引用条款用程序化比对（引用了真实存在的条款）。
- **图纸审查**：标注缺陷清单，比对召回率 / 误报率。

## 3. 评测集格式（jsonl）

`data/eval/` 下按能力命名，每条为：

```json
{
  "id": "calc-0001",
  "type": "calc",
  "input": {"kind": "velocity", "diameter_mm": 150, "flow_lps": 20},
  "gold": {"velocity_mps": 1.13, "unit": "m/s"},
  "tolerances": {"relative": 0.01, "absolute": 0.001},
  "formula": "explicit_formula_name",
  "spec_ref": "GB 50015-2019 4.4"
}
```

```json
{
  "id": "rag-0001",
  "type": "rag",
  "query": "建筑生活给水立管最小管径是多少？",
  "gold_articles_any": ["GB50015-2019 5.4.2"],
  "gold_articles_all": [],
  "forbidden_articles": [],
  "eval": "citation_exists"
}
```

## 4. 跑分器（harness/runner.py）

对每条评测集执行对应 subgraph，收集：
- `correct`（数值/标签比对）或 `judge_score`（LLM-judge 1-5）
- `latency_ms`, `cost_usd`, `citations`, `trace_id`

输出聚合报告 + 与基线比较（增量/回归）。CI 门槛必须数值化：默认核心计算通过率不得下降超过 2 个百分点，引用正确率不得下降超过 3 个百分点，且不得出现新增核心测试失败。

## 5. 观测与反馈回流

- **LangSmith / Langfuse**：作为可选外部观测后端；P0 先保证本地 JSON trace，未配置凭据时不能阻塞运行。
- **线上反馈**：前端「反馈」按钮标记差的回答 → 回流为候选评测集 → 人工标注 → 加入金标准。
- **CI**：harness 作为 CI 门禁，改动导致基线指标显著下降则拦截合并。

## 6. 给排水领域评测要点

- 规范条文**有版本**：评测时要标 `spec_ref` 的版本，Agent 必须引用正确版本。
- 计算**口径敏感**：同一个物理量在不同公式（如沿程水头损失用 Darcy-Weisbach vs 舍维列夫公式）下结果不同，评测必须**固定公式口径**并写入 `input`。
- 图纸审查评测需要**真实或人工构造的含缺陷图纸**，前期可用构造的可疑图元。
