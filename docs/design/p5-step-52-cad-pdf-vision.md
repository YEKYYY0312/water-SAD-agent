# P5-S52 规格与决策：CAD 导出 PDF → 视觉模型看图

日期：2026-09-29　状态：已交付（真实百炼 Qwen-VL 端到端实测）　前置：S48/S49

## 问题

CAD 导出的 PDF 只有矢量线条，文字也被转成了曲线，没有文字层，pypdf 抽出来是 0 字，agent 只能回答"读不到"。设计院最常交付的就是这种 PDF。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **只对文本层基本为空的 PDF 看图**（平均每页不足 40 字）；有正文的 PDF 不调视觉模型 | 文字已经读到了，再花钱看图只会引入误读 |
| D2 | 渲染用 `pypdfium2`（BSD-3/Apache-2.0，自带 PDFium 轮子）；PNG 编码**只用标准库**（zlib + struct），不引入 Pillow | S48 已拒绝 AGPL 的 pymupdf；为了一次编码引入带 C 扩展的依赖不值得 |
| D3 | 模型默认用 **`MODEL_NAME`**，可通过 `WATER_AGENT_VISION_MODEL` 改 | 同一张图实测：flash 快一倍（18.6 s 对 39.7 s），但把"絮凝沉淀池"读成"紫菜沉淀池"、"I 期工程"读成"男工棚"。审图时误读代价高 |
| D4 | **第 7 个远程出口**：`ProviderKind.BAILIAN_VISION` / `CallCategory.VISION_REVIEW`，经 `ProviderGateway`（限流、预算预留、重试 2 次、401/403 零重试、熔断、usage 对账），登记进 `PROVIDER_CALL_SITES`，出站静态扫描覆盖；`governance_coverage` 从 6/6 改为 7/7 | 与其他出口同一套治理，没有绕行 |
| D5 | 输出整段加上【视觉审阅结果】头：**图像转写，可能误读，不是图纸原文也不是程序化校验；数值不得直接用于计算；规范判断仍须检索引用**。提示词要求"看不清就写看不清、不推测、注明位置" | 铁律 1、2 |
| D6 | 有界：每次上传最多 4 页，渲染长边 2000 px（实测约 2,500 image token），输出上限 2000 token；超出的页数会如实声明未审阅 | 控制成本与延迟 |
| D7 | 视觉失败（无 Key、403、超时、渲染失败）→ **上传照样成功**，正文写【视觉审阅未执行】并附原因 | 文本层为空本来就读不到，视觉只是增强；静默失败会让模型以为这份 PDF 没有内容 |
| D8 | 开关 `UPLOAD_VISION_ENABLED`（默认开）；`tests/conftest.py` 在测试中默认关闭 | 防止测试因为本机有 Key 而悄悄产生计费调用 |
| D9 | 能力说明与前端卡片如实区分"已看图（可能误读）"和"看图未执行" | S49 纪律 |

**数据外发**：页面图像会发送到百炼（阿里云）。数据等级为 `project_doc`，与 docgen 润色同级。需要内网部署时，把 `UPLOAD_VISION_ENABLED` 设为 `false` 即可关闭。

## 实测（2026-09-29）

- 测试样本：用 ezdxf 把真实样图 P-02 渲染成矢量 PDF，与 CAD 打印 PDF 同构：pypdf 抽出 0 字，图面有中文标注。**用户的真实 CAD 导出 PDF 尚未实测**，本机没有样本。
- 模型对比（单页 A3，1:500 管道总平面图）：
  - plus：39.7 s，输入 2,654 token（其中 image 2,522），输出 1,500 token（达到上限，被截断）。
  - flash：18.6 s，token 数相同，误读更多。
- 容器端到端（真实 MODEL_NAME + DeepSeek）：
  - 上传返回 201，**耗时 59.6 s**，抽出 2,755 字、6 个分块。
  - 附图提问后运行 `succeeded`（11.4 s），回答分为"图上有什么 / 需要核对的地方 / 依据边界"三部分，明确写出"属于图像转写、可能误读，数值不得直接用于计算"。没有编造规范引用，而是主动提出"需要规范判断可以再检索"。
  - **实测误读**："絮凝沉淀池"被读成"紫凝沉淀池"，"网孔钢管复合塑料管段"被读成"河北钢管复合塑料管段"。模型自己把后者标成了"文字存疑"。这正是 D5 标注存在的原因。
- `ci_gate.sh` 全绿；compose smoke 30/30；前端测试 47/47。

## 残余

- **上传要等约 1 分钟**（一页一次视觉调用，同步执行）。前端只显示进度条，看不出这段时间是在"看图"。后续考虑改为异步入库，并显示"正在看图"状态。
- 视觉调用发生在上传阶段，**不属于任何 run**：usage 只记进 gateway 的预算账本，不进 run trace，运行检查面板里看不到这笔费用。
- 输出上限 2000 token，信息量大的图会被截断；逐页、分区看图（先切成四块再分别看）是后续优化。
- 没有视觉识别质量的评测集，**不得声称识图准确率**。
- 价格：`MODEL_NAME` 的单价以百炼控制台为准，未录入 `ModelPrice`，所以不做成本硬限制，只受 token 限流约束。
