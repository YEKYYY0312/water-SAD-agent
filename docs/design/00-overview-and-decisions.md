# 给排水 Agent —— 总体设计与决策记录（V0.1）

> 本文档是给排水 Agent 工程的**基准文档**，后续所有迭代以它为准。遵循《AI Engineering》(Chip Huyen) 的方法论，核心是 **Harness Engineering（评测框架工程）** 与 **Loop Engineering（循环工程）**。

## 1. 项目愿景

构建一个面向**给排水工程**的 AI Agent，能够：
- 检索并引用国家/行业规范（GB 50015、GB 50013、GB 50014、设计手册、标准图集）
- 进行水力计算（管径、流量、流速、水头损失、水泵扬程、排水坡度）
- 读取图纸（DWG）并做合规性审查
- 生成计算书/设计说明
- 统计工程量与材料

## 2. 已确认的决策（用户拍板）

| 决策项 | 选择 | 理由 |
|---|---|---|
| 核心场景 | 全部 5 类（规范问答/水力计算/图纸审查/计算书生成/材料统计） | 统一架构承载，按性价比分阶段落地 |
| 部署形态 | 个人本地开发，先用云端 API 快速验证 | 快速跑通，数据暂非敏感，后续可内网化 |
| 文件类型 | PDF / Word / Excel / DWG | DWG 最难，单独后置一个阶段 |
| 模型 | 云端 API（DeepSeek / Qwen / OpenAI） | 中文规范理解强，上手快 |
| MCP | 框架先行，自研 + CAD/BIM + 企业库后续接 | 先落地核心（计算引擎+规范库），其余占位 |

## 3. 核心工程判断：MVP 优先排序

DWG 图纸解析与企业级 MCP 集成是**体量最大**的两块，且依赖前面 RAG/计算/文档能力的成熟。因此：

> **别让最难的部分阻塞 MVP。** 统一架构承载全部能力，但按「价值/难度比」分阶段交付，每一阶段同时交付其评测集。

## 4. 技术栈

| 层 | 选型 |
|---|---|
| 编排 | LangGraph（StateGraph + checkpointing + interrupt） |
| 组件/RAG | LangChain（document loaders, retrievers, rerank） |
| 工具标准化 | MCP（Model Context Protocol） |
| 后端服务 | Python（FastAPI，供前端调用） |
| 前端 | React（聊天 + 上传 + 工具可视化 + 图纸预览） |
| 评测/追踪 | LangSmith（或开源 Langfuse）+ 自建 harness |
| 检索 | TriviumDB（向量×图谱×文档，目标使用 `search_hybrid`）+ Retriever 适配器 |

## 5. 关键设计哲学

1. **计算类永远走程序化校验**，不让 LLM 做数值计算/口算 —— 这是给排水 Agent 可靠性的底线。
2. **引用可追溯**：每个回答要能指回具体规范条款（编号 + 条号），这是工程场景的硬要求。
3. **Human-in-the-loop**：生成正式文档/关键设计输出前暂停等待人工确认（LangGraph `interrupt`）。
4. **评测先行**：每个能力上线前先有金标准评测集，上线后有回归防止退化。

## 8. 设计决策记录（ADR）—— 已确认方向与未锁定项

> 这些是工程设计阶段需要记录的关键决策。ADR-01 仍需由具体项目或评测用例显式指定。
> 当前只固化已确认的工程约束；公式口径保持可配置，不能由实现者静默决定。

| ADR | 决策 | 推荐默认值（当前设计暂按此） |
|---|---|---|
| ADR-01 | 沿程水头损失公式口径 | 不锁定具体公式；每个计算用例显式指定公式 |
| ADR-02 | 规范条款检索粒度 | 两级索引：检索到「条」，返回「节/章上下文 + 条款」 |
| ADR-03 | 图纸审查路线 | 规则引擎为主 + Vision 辅助 |
| ADR-04 | Human-in-the-loop 位置 | 仅在生成正式文档/设计说明前设确认点 |
| ADR-05 | 评测判分权重 | 计算=程序化硬门槛(≤1%)；引用=精确到条；两者不妥协 |

以下为各 ADR 的详细理由与候选方案。ADR-01 当前不锁定具体公式；其余工程方向按本文执行。

### ADR-01 沿程水头损失公式口径（最重要）
- **状态**：未锁定，需按项目或评测用例显式指定
- **背景**：同一工况下不同公式结果不同（且差异可能超过判分阈值），评测必须锁定口径。
- **候选**：舍维列夫 / 海曾-威廉 / Darcy-Weisbach / 巴甫洛夫。
- **执行规则**：支持舍维列夫、Darcy-Weisbach、Hazen-Williams、曼宁等公式；计算输入和评测 gold 必须显式包含 `formula`。
- **禁止行为**：缺少公式或必要参数时，不得静默切换公式，必须返回结构化的参数缺失或待确认状态。

### ADR-02 规范条款检索单元（粒度）
- **状态**：已确认（P1 升级为结构化父子级切块，见 08-ingestion）
- **背景**：影响 RAG 召回精度与引用可追溯性。
- **候选**：按「条号」切为检索单元 / 按「节(章)-条款」两级（节为上下文、条款为答案）/ 结构化父子级切块（父块=章/节，子块=条/款/项/表 + 递归兜底）
- **推荐**：**结构化父子级切块** —— 检索命中子块（条/款/项/表），按 `parent_id` 回填父块（章/节）上下文；最终引用绑定子块 `article`（如 `GB50014-2021 4.4.2`）。
- **理由**：保留规范引用精度（不允许用父块替代条款），同时用父块上下文提升回答质量；表格与限值单独成块避免截断。

### ADR-03 图纸审查路线
- **状态**：已确认，P3 再细化规则
- **背景**：DWG 合规审查是难度与工作量最大的能力。
- **候选**：规则引擎为主 + Vision 辅助 / Vision 为主。
- **推荐**：**规则引擎为主**（规范条文 → 可执行检查规则），Vision 做图元/图面理解辅助。
- **理由**：规则可解释、可控、可评测（召回/误报可量化）；Vision 用于非结构化图面信息。

### ADR-04 Human-in-the-loop 位置
- **状态**：已确认
- **候选**：仅生成正式文档前确认 / 每个关键计算与检索都要确认。
- **推荐**：**只在「生成正式文档/设计说明」前设确认点**；常规问答与计算自动完成。
- **理由**：兼顾可靠性与使用流畅度，避免频繁打断。

### ADR-05 评测判分权重
- **状态**：已确认
- **背景**：决定评测集与回归里两种用例的比例与准入阈值。
- **候选**：更重「计算绝对正确」 / 更重「引用规范精准」。
- **推荐**：**两者并重但分流** —— 计算类用程序化数值判分（硬门槛，误差≤1%）；
  规范问答用引用可追溯 + LLM-judge（要求引用精确到条款）。给排水工程两者都不可妥协。
- **理由**：数值错是硬伤，引用错是信任丧失，都不允许。
