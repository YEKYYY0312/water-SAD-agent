## 交付

- **`documents/drawing_upload.py`**：DXF 魔数校验与上传审查。
  - 魔数：ASCII 文件要求首个组码为 `0` 且其后是 `SECTION`；二进制 DXF 按哨兵识别；改名为 .dxf 的 DWG（`AC10xx`）单独给出"另存为 DXF"提示。
  - 审查在**只含 `drawing.dxf` 的临时目录**里跑（root 就是这个目录，`read_dir_allowed` 与 `relative_to` 两道防线原样生效），用完即删。
  - 报告通过审查子图的 `_build_report` / `render_report_text` 生成，报告格式只有这一处定义；只替换标题里的登记号，并加一个计数前言。
- **`extractors.py`**：白名单加入 `.dxf`，抽取产物就是审查报告（engine `dxf-review`）。新增 `ExtractedDocument.suspicious`，用来带出注入图元：报告里没有图元原文，分块护栏看不到这些文字，可疑标记必须从抽取阶段带出来。
- **迁移 `0006_step50_dxf_uploads`**：`ck_uploads_suffix` 放行 `.dxf`（用 batch 模式，SQLite 与 PG 通用）。`MIGRATION_HEAD` 三处同步：database.py、compose.yml 的 smoke、test_memory_store。
- **`dxf_reader.read_drawing`**：截断的 DXF（头部合法、缺 EOF）会让 ezdxf 抛 `StopIteration`，现在收进 `DRAWING_UNREADABLE`。这是**上传测试新暴露的真实缺陷**：违反了该函数"永不抛出"的契约，在协程里还会变成 RuntimeError。已加回归参数。
- **能力说明**（`file_context`）随白名单推导：DXF 可上传并自动审查，转述时必须保留未检查项；DWG 暂不支持。
- **前端**：`.dxf` 可选；`UPLOAD_TYPE_NOT_ALLOWED` 文案提示 DWG 另存为 DXF；文件卡片从报告首句固定格式读出"已审查 N 条管段，M 条待核问题，K 项未检查"，列表接口没有预览时不猜数字。

## 追加修复（2026-09-29，用户实测"图纸 + 计算书对照核对"后）

用户实测暴露了三处问题，都已修复：

1. **零引用收口失败**：模型在正文里写了"GB 50014-2021 第 7.4.3 条"，却两次都没调用 `cite_clauses`。
   - 校验器新增 `_mentioned_source_ids`：把正文中出现、且在检索上下文里真实存在的条款号列给模型，要求它补一次声明。
   - 校验器**只提示、不代为声明**，引用仍然必须由模型自己通过 `cite_clauses` 登记。代填就回到了 legacy 的"citation_ok 恒真"。
2. **"只有公式没有结果"的根因在抽取环节**：python-docx 的 `paragraph.text` 会整段跳过 Word 公式（`m:oMath`）。
   - 这份计算书有 114 个公式，全部丢失。
   - 新增 `documents/omml.py`：把公式按结构转写成线性文本（分式、上下标、根式、函数），**不求值，数字按原样保留**，计算仍由程序化工具完成（铁律 1）。
   - 另有 70 个 MathType OLE 对象只有图片，读不到，只计数并如实写进正文末尾。
   - 实测结果：抽取文本从 11,642 字增加到 15,042 字，`【公式】` 105 条，格栅间隙数、宽度、水头损失的代入值和结果都读出来了。
3. **"读不到图面信息"**：原先上传后只保留规则审查结论。
   - 现在在审查报告之后另起一节 `【图面信息摘要】`：标注文字按编号、坐标、标高、规格/参数、其他文字分组，附带图层、图元、图块计数。
   - 图签和会签栏里的固定字样（审核、DESN. 等）会被滤掉；命中注入规则的标注不进摘要。
   - 摘要**不做推导**：不会用标高相减算坡度，也不会把坐标连成管线。并在摘要里明写"管线走向和连接关系未转写"。

**实测**（真实 DeepSeek，P-05.dxf + 137400 计算说明书同时附上，问"核对是否一致"）：
- run 为 `succeeded`，6 条引用都通过了 `cite_clauses` 校验。
- 回答读出了图名"污水深度处理站 站区总平面布置图"、构筑物清单和 14 条标高，发现图纸标高（15.8–22.4 m）与计算书厂址高程（145.00 m）相差约 120 m。
- 读出了格栅计算的代入式。原文分母写的是 `2×9.8×0.5×0.8`（经核对原文确实如此），而公式要求是 b·h·v，模型指出这是代入错误。
- 还发现了模板占位符"（10+学号后两位 1/2）"没有替换。
- 计算书 39 段只读了 8 段，属于 `complete=False`，回答里如实说明了读到的范围。

**残余**：
- 附件预算为 6,000 字，两份文件平分之后，长计算书仍然只能读到一部分；需要追问具体章节，或者单独附上。
- 摘要只转写文字，管线几何与连接关系仍未结构化，这属于 P3 的范围。
- MathType 公式读不到。
