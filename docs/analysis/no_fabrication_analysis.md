## 一、执行摘要

在 RAG P1 质量复测中，**7 例**案例的 `no_fabrication` 维度被 LLM-as-judge 评为 **3 分**（满分 5 分，阈值 4 分），占总数的 **12.07%**。

**核心问题**: 模型在调用 `cite_clauses` 工具时，**引用了检索上下文中未出现的条款号**。

**关键发现**:
- ✅ **条款内容本身正确**：判定理由均指出"内容与上下文一致"、"未编造事实性内容"
- ⚠️ **条款号不可追溯**：引用的条款号（如 `GB50014-2021 5.1.4`）未在检索上下文的 `article_id` 字段中出现
- 🔍 **疑似模型"幻觉"**：模型可能从训练数据记忆中补充了正确但未检索到的条款号

**影响评估**: 
- 对用户：回答内容正确，但引用不可追溯，影响审计和可信度
- 对系统：违反了"引用必须可追溯到检索结果"的设计原则

### 案例 1：综合生活污水定额如何确定？（Line #6）

**期望条文**: `GB50014-2021 4.1.14`  
**实际引用**: `GB50014-2021 4.1.14`, `GB50318-2017 4.2.3`, `GB50318-2017 4.1.4`

**判定理由**（摘录）:
> 回答中引用的多个具体条款号（如GB 50014-2021第4.1.14条、GB 50318-2017第4.1.4条、第4.2.3条、第4.2.4条）在检索上下文中并未出现，属于编造或推断的条款号，但**核心数值和内容有上下文依据，未完全脱离事实**。

**问题分析**:
- ✅ 模型正确命中了 gold 条文 `GB50014-2021 4.1.14`
- ✅ 引用的条款号在语义上是正确的（如果真实核查规范本体）
- ❌ 但这些条款号未在本次检索返回的 `context_articles` 中出现
- ❌ 违反了"引用必须可追溯"的原则

**疑似根因**: 模型从训练数据中"记住"了这些条款号的存在，在生成引用时补充了它们。

## 五、根因分析

### 5.1 可能的技术原因

#### 原因 1：模型"幻觉"（最可能）
- **现象**: 模型在训练数据中见过完整的 GB50014-2021 / GB50013-2018 等规范
- **行为**: 在生成回答时，从记忆中"补充"了正确但未检索到的条款号
- **证据**: 判定理由指出"条款内容与上下文一致"，说明模型并非随机编造

#### 原因 2：检索结果的 article_id 字段不完整
- **现象**: TriviumDB 返回的 `context_articles` 可能只包含条文内容，但 `article_id` 字段为空或格式不统一
- **行为**: 模型无法从 context 中提取可用的条款号，只能依赖记忆
- **排查方向**: 检查 `context_articles` 的实际结构

#### 原因 3：cite_clauses 工具缺乏硬约束
- **现象**: `cite_clauses` 工具的 prompt 可能未明确要求"只能引用 context 中出现的条款"
- **行为**: 模型认为补充相关条款号是"有帮助的"，未意识到违反了可追溯性原则
- **排查方向**: 审查 `cite_clauses` 工具的 schema 和 prompt

## 六、修复建议

### 优先级 P0：在 cite_clauses 工具中添加硬校验

**目标**: 拒绝接受不在 `context_articles` 中的条款号

**实现方案**:
```python
def cite_clauses(article_ids: list[str], context_articles: list[dict]):
    """引用条文工具（带可追溯性校验）"""
    valid_ids = {a['article_id'] for a in context_articles if 'article_id' in a}
    
    for aid in article_ids:
        if aid not in valid_ids:
            raise ValueError(
                f"条款号 '{aid}' 不在检索上下文中。"
                f"可用的条款号：{sorted(valid_ids)}"
            )
    
    # ... 正常执行引用逻辑
```

**预期效果**: 
- 模型第一次尝试引用不存在的条款号时，工具会返回错误 + 可用条款列表
- 模型根据错误消息修正引用，只使用检索到的条款号
- `no_fabrication` 评分提升至 5 分

---

### 优先级 P1：在 cite_clauses prompt 中强化约束

**目标**: 让模型明确"只能引用 context 中的条款"

**修改位置**: `src/water_agent/tools/cite.py` 的工具描述

**修改前**（推测）:
```python
description = "引用规范条文。传入条款号列表，系统会记录引用关系。"
```

**修改后**:
```python
description = """引用规范条文。

⚠️ 重要约束：
- 必须且只能引用检索上下文（context）中出现的条款号
- 禁止从记忆中补充未检索到的条款号
- 如果需要的条款未在 context 中，应说明"根据已检索到的条文..."

传入条款号列表，系统会验证可追溯性并记录引用关系。
"""
```
