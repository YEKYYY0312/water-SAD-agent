## 二、实施内容

### 1. 增强系统类型识别（mapping.py）

#### 新增 `infer_system_from_annotation` 函数
从标注文本推断系统类型，支持关键词：
- **排水系统**: 污水、废水、雨水、排水、WL、PL、FL、YL、WS、FS
- **给水系统**: 给水、自来水、JL、GL

#### 更新 `map_pipes` 逻辑
系统类型识别优先级：
1. 图层名识别（`_layer_system`）
2. 标注文本推断（`infer_system_from_annotation`）
3. 全局上下文推断（`_apply_global_system_inference`）

### 2. 全局推断增加管径限制（mapping.py:428）

**关键改动**：
```python
# Before (P4):
if pipe.system is None:

# After (P5.1):
if pipe.system is None and pipe.dn_mm is not None and pipe.dn_mm >= 200:
```

**理由**：
- 只对 DN ≥ 200 的管段应用全局推断
- 避免将室内立管（DN100-150）误判为室外排水主管
- 室外排水主管通常 DN ≥ 200

### 3. 恢复规则严格模式（rules.py:283）

`check_min_diameter` 恢复 P4 之前的检查策略：
- **只检查 system=drainage 的管段**
- system=None 或 system=water_supply 的管段不检查

## 四、剩余 2 个误报分析

### 误报详情
- **图纸**: P-02
- **handle**: 2167, 236B
- **管径**: DN110
- **图层**: `$TD_AUDIT_GENERATED_(1613)`, `0`

### 误报成因
1. 附近标注文本 "浓污水集中池" 包含 "污水" 关键词
2. `infer_system_from_annotation` 识别为 drainage 系统
3. DN110 < 300 → 触发缺陷报告

### 为什么是合理的误报
1. **标注文本确实包含排水关键词**：规则逻辑正确执行
2. **语义上下文特殊**：这是污水处理设施内部管道，不适用室外主管 DN300 要求
3. **进一步降低需要更复杂的上下文理解**：识别管道是否在处理设施内部
