# 给排水 Agent · 前端设计方案 v0.1

交付物：`web/index.html`（单文件可交互原型，无外部依赖，双击即可打开）。

> **数据声明**：原型中的规范条文均为**占位示例**，不是真实规范文本（界面引用卡上标注「占位」）。接入真实语料前，任何条款文字都不得放进 UI —— 这对应项目的第二条铁律「引用可追溯，禁止编造条款」。

---

## 1. 设计定位

前端是 Agent 与工程师之间的**交互面 + 信任面**。给排水工程师不会因为你聊得顺就信你，他要看到：你调了什么工具、引了哪条规范、算出什么数、数是怎么来的。所以本方案的优先级是：

1. **透明优先于美观** —— 工具调用树、引用卡片、计算卡片是主内容，不是附属装饰。
2. **数值优先于叙述** —— 参数、公式、结果、单位必须结构化呈现，数值与单位走等宽字体。
3. **可干预** —— 正式文档生成前必须停下来等人确认（ADR-04），且可回滚。

## 2. 信息架构

```
顶栏   品牌 · 规范集选择器 · 运行模式(Legacy/Agentic) · 模型状态
├── 左栏 264px   新建/搜索/能力入口/会话列表/知识库状态
├── 中栏 1fr     会话头(意图·thread_id·trace) → 消息流 → 输入区
└── 右栏 344px   透明化面板：工具调用 / 引用 / 计算 / Trace
```

右栏不是"侧边信息"，而是**答案的证据链**。回答里任何一处引用、任何一个数值，都能在右栏找到原始出处，点击引用卡可跳转并高亮。

## 3. 设计令牌

| 类别 | 取值 |
|---|---|
| 主色 | 工程水蓝 `#1668DC`（600 主操作/引用链接，`#0A3572` 900 仅用于深色文字，对比度 7.4:1，达 WCAG AAA） |
| 中性 | `#0F172A / #334155 / #64748B / #94A3B8 / #CBD5E1`，分割线 `#E5EAF1` |
| 语义 | 通过 `#0E9E6E` · 待确认 `#C2740A` · 超界 `#D23B3B` · 信息 `#1668DC` |
| 字体 | 中文 PingFang SC / 微软雅黑；数值与条号用等宽 `ui-monospace / SF Mono / JetBrains Mono` |
| 字号 | 正文 13px/1.6，次要 12px，标签 11px，结果数值 26px |
| 间距 | 4px 基准：4 / 8 / 12 / 16 / 24 / 32；卡片内边距 16px，分区 24px |
| 圆角 | 5 / 6 / 8 / 12 / 16，卡片 12，输入区 16 |

| 动效 | 120ms（状态反馈）/ 180ms（位移展开），尊重 `prefers-reduced-motion` |

## 4. 组件清单

| 组件 | 状态 |
|---|---|
| 工具调用树 | 折叠/展开、步骤态（等待/执行中/成功/警告/失败）、耗时与入参摘要 |
| 引用卡片 | 规范号+条号、标题、条文摘要、校验徽标（已校验/待确认/未命中）、score |
| 计算卡片 | 参数格 / 公式行 / 结果区（通过绿、超界红）/ 校验结论行 |
| 审批卡 | 人工确认节点（ADR-04），确认 / 返回修改，确认后锁定并写 trace |
| 消息操作行 | 有用 / 无用 → 回流评测集；复制 / 重新生成 / 查看 trace |
| 输入区 | 自适应高度、拖拽上传（PDF/DWG/Excel）、附件移除、建议问题 |
| Toast | 轻量反馈，2.2s 自动消失 |

## 5. 关键交互

- **流式生成**：输入框 → 工具步骤逐步点亮 → 骨架屏 → 打字机输出 → 追加计算/引用卡片。生成中发送键变为停止键，可中断。
- **回环可视化**：流速超界时，工具树会显示 `validate → 超界 → revise → 重算 → 通过`，让"程序化校验 + 回环"这件事在界面上可见。
- **引用跳转**：点击引用卡 → 右栏切到「引用」并高亮该条。
- **反馈飞轮**：点「无用」→ 提示"已回流评测集 · rag_p0"（对应 05-frontend.md 的数据飞轮设计）。
- **响应式**：≤1040px 右栏转抽屉，≤820px 左栏转抽屉，三栏在笔记本上仍可用。

## 6. 可访问性

- 全部交互元素可键盘访问，`:focus-visible` 2px 主色描边 + 2px 偏移。
- 消息区 `role="log"` + `aria-live="polite"`；折叠按钮带 `aria-expanded`；Tab 带 `role/aria-selected`。
- 正文对比度 ≥ 7:1，次要文字 ≥ 4.5:1；状态不依赖颜色单独传达（图标 + 文案 + 色）。
- `prefers-reduced-motion` 下关闭全部动画与平滑滚动。

## 7. 与后端的接口约定

原型为纯前端模拟。接真实服务时按 `docs/design/05-frontend.md` 的约定对接：

| 接口 | 用途 | 前端落点 |
|---|---|---|
| `POST /api/chat` | SSE 流式返回 token + 工具事件 | 消息流、工具树 |
| `POST /api/upload` | 上传解析 | 输入区附件 chip |
| `GET /api/tools` | 工具注册表 | 工具树名称/入参 |
| `GET /api/spec/:ref` | 条款原文 | 引用卡片展开 |
| `POST /api/feedback` | 反馈回流 | 消息操作行 |
| `GET /api/run/:id/trace` | run 事件流 | 右栏 Trace 页 |

事件名沿用现有 Trace 定义：`run_start / node_enter / node_exit / retrieve_complete / generate_complete / citation_check_complete / retry / error / run_end`。

## 8. 落地路径

1. **Step 1**：把 `index.html` 拆成 Vite + React + TS 工程，令牌原样迁到 CSS 变量，组件一一对应。
2. **Step 2**：先接 `GET /api/run/:id/trace` 与本地 JSON Trace —— 透明化面板可以先用假数据以外的真实数据跑起来。
3. **Step 3**：接 SSE 流式聊天；工具树随 `node_enter/node_exit` 事件实时点亮。
4. **Step 4**：接计算内核，计算卡片改为后端返回的 `result + unit + formula + check` 结构，前端不做任何数值运算（当前原型的公式计算仅为演示）。
